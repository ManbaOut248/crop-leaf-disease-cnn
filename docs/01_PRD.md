# 基于 CNN 的农作物叶片病害识别系统 — 产品需求文档（PRD）

> 版本：V1.0（设计阶段 M1）
> 关联文件：项目任务书 V1.0.0、要求.txt、UI/UX 设计、数据库设计、API 接口文档
> 类别口径：经与需求方确认，采用**真实数据集 38 类**（任务书文字写「26 类」，实测数据集为 PlantVillage 38 类 / 54,420 张，任务书「约 5.4 万张」与 38 类一致，「26 类」视为笔误）

---

## 1. 产品概述

### 1.1 背景
农作物病害是制约粮食与经济作物稳产增产的重要因素。传统诊断依赖农技人员肉眼观察，经验依赖强、基层力量不足，常错过最佳防治窗口。基于卷积神经网络（CNN）的叶片病害分类在公开数据集上已达接近专家水平。本项目以 ResNet18 为骨干，构建 Web 端识别应用，农户/农技人员手机拍照上传即可获得病害判读与防治建议。

### 1.2 总体目标
开发一款基于 ResNet18 的农作物叶片病害识别 Web 应用：用户通过浏览器上传叶片图像 → 系统自动识别病害类别（覆盖 **14 种作物、38 类病害及健康状态**）→ 返回置信度、Top-3 候选概率分布与防治建议。

### 1.3 量化指标（对齐任务书 2.2.3）
| 指标 | 目标 |
|---|---|
| 总体分类准确率 | ≥ 85% |
| 各类别 F1 分数 | ≥ 0.80 |
| 单张推理耗时（GPU） | ≤ 300 ms（不含网络传输） |
| 支持图像格式 | jpg / png / jpeg / bmp |
| 输入分辨率 | 224 × 224（预处理后） |
| 浏览器兼容 | Chrome / Firefox / Safari / Edge 最新两个大版本 |

## 2. 目标用户与使用场景

| 角色 | 场景 | 核心诉求 |
|---|---|---|
| 基层农技人员 | 田间巡诊，批量拍照初筛 | 快速、批量、可导出记录 |

## 3. 功能需求清单（FR）

### 3.1 图像上传模块（FR-UP）
- FR-UP-01：支持点击选择与拖拽上传。
- FR-UP-02：校验格式（jpg/png/jpeg/bmp）与大小（≤ 10 MB/张）。
- FR-UP-03：上传后即时预览原图。
- FR-UP-04：**作物类型必选**（清单来自 `GET /crops`），未选择时「开始识别」按钮禁用；页面明示「仅支持列表内作物的叶片」。
- FR-UP-05：常驻**拍法引导**（单片叶片近景 ✓ / 整株远距离 ✗ 的内联图示 + 3 条要点）。
- FR-UP-06：提供**单片裁剪**：300×300 固定取景窗 + 1–4× 缩放，从原图取景并导出 448×448，确认后自动重新识别；产物文件名追加「__裁剪」后缀。
- FR-UP-07：**批量识别（2026-10-30）** —— 识别页提供「单张 / 批量」模式切换，批量模式一次可选 1~9 张，逐张独立识别；每张都写入识别历史。
- FR-UP-08：**整批同一作物前置提示** —— 批量模式下作物只选一次、整批共用；页面常驻警告「整批图片必须是同一种作物」，并在每次开跑前弹确认框（写明张数与作物名、说明混入其他作物会被强行判成本作物病害），用户确认后才发起识别。
- FR-UP-09：批量模式**已选图片以 3 列缩略图逐张可见**（带序号与单张删除），供用户在识别前逐张核对是否同一作物；超过 9 张时明确提示「多出的已忽略」而非静默丢弃。

### 3.2 图像预处理模块（FR-PRE）
- FR-PRE-01：缩放至 224×224。
- FR-PRE-02：RGB 归一化（ImageNet 均值/方差）。
- FR-PRE-03：格式统一转换，异常图像给出友好提示。

### 3.3 深度学习识别模块（FR-CLS）
- FR-CLS-01：基于 ImageNet 预训练 ResNet18，38 分类输出。
- FR-CLS-02：返回预测类别、置信度（softmax 概率）。
- FR-CLS-03：返回 Top-3 候选类别及概率。
- FR-CLS-04：模型离线加载，服务启动即就绪。

### 3.4 结果展示模块（FR-RES）
- FR-RES-01：展示预测病害中文名 + 置信度。
- FR-RES-02：Top-3 概率条形图可视化。
- FR-RES-03：展示病害特征说明与防治措施建议（来自知识表）。
- FR-RES-04：附农技服务免责声明。
- FR-RES-05：Top-3 每个候选旁展示该类**病害参考图缩略图**，点击可看 3 张数据集原图（含来源说明）。
- FR-RES-06：误判时提供行内入口「框选单片叶片再识别一次」，直接进入裁剪流程。
- FR-RES-07：**跨页记忆** —— 切页或刷新后恢复上次的作物 / 图片 / 结果，并明确标注「这是上次识别的结果」；关闭标签页即清除。
- FR-RES-08：**批量结果以 3 列卡片网格呈现**，每卡显示缩略图、状态标签（健康 / 病害 / 可能非叶片 / 置信度低）、病害中文名、文件名、置信度；顶部汇总条给出「共 N 张 · 成功 X · 失败 Y」与健康 / 病害 / 可能非叶片 / 置信度偏低四项计数。
- FR-RES-09：批量中**单张失败不影响其余**：能识别的先出结果，失败项单独列出文件名与原因；结果的 `index` 与上传顺序对齐，中间有失败也不会导致后续卡片错位。
- FR-RES-10：点开批量结果中的单张，可查看该张的 Top-3、参考图、症状与防治，并支持**框选单片叶片后重新识别** —— 只重识别这一张（在历史新增一条记录，不覆盖原记录），结果贴回原卡片而非新增卡片。
- FR-RES-11：批量结果**不写入会话记忆**（9 张图的快照会撑爆 sessionStorage 约 5MB 的配额），页面显式提示「切页后请到识别历史查看，每张都已落库」。

### 3.5 历史记录模块（FR-HIS）
- FR-HIS-01：登录用户可保存识别历史（图、结果、时间）。
- FR-HIS-02：列表查看、原图与结果对比。
- FR-HIS-03：支持导出（CSV/JSON，**全量**导出而非当前页）。
- FR-HIS-04：历史数据统计可视化 —— 累计识别数、涉及作物数、平均置信度、需复核数四项概览。
- FR-HIS-05：作物分布图（横向柱状，按条数降序）。
- FR-HIS-06：置信度分布图（6 档直方图，**须标注为原始 softmax，与页面的校准后可靠性标签区分口径**）。
- FR-HIS-07：近 30 天识别量趋势（无记录日期补零）。
- FR-HIS-08：非叶片拦截监控（拦截率 / MSP 回退数），复用 `/records/ood-stats` 聚合。
- FR-HIS-09：记录数不足 10 条时不渲染分布图，仅显示数字卡与引导提示（避免"每根柱子都是 1"的无效图表）。
- FR-HIS-10：列表**服务端分页**（`?page=&size=`），页脚显示「第 X-Y 条 / 共 N 条」；排序需带二级键保证全序，避免同秒记录翻页重复。
- FR-HIS-11：**自定义命名**（≤40 字符，清空即恢复原始文件名）；展示按「自定义名 → 原始文件名 → 历史图片 #id」三级回落。
- FR-HIS-12：**人工判断 = 给 AI 判卷** —— 用户已知道真实病害，对「AI 这一次的输出」给结论：`识别正确` / `识别错误` / `未核对` 三态，列表与详情两处均可设置；**不需要用户提交自己的答案**，也不允许修改预测类别与置信度（那是识别时的客观事实）。
  - 文案必须写「识别正确 / 识别错误」而非「判断正确 / 判断错误」：后者会被读成「操作人自己判断失误」，与设计意图相反。
- FR-HIS-13：**人工核对统计** —— 准确率分母为已核对条数；一条未核对时显示空状态而非 0%。
- FR-HIS-14：**详情为居中弹窗**，原图可放大（缩放/旋转/重置），并展示当时的 Top-3 候选与对应病害参考图。
- FR-HIS-15：**删除单条记录**（二次确认），同时清理磁盘原图。
- FR-HIS-16：每张统计图表**可单独隐藏**，隐藏后同行剩余卡片自动补位；配套界面偏好开关见 FR-UI-01。
- FR-HIS-17：**按人工判断筛选列表** —— 四档：全部 / 仅识别错误 / 仅识别正确 / 未核对，每档带**全量历史**条数徽标；切换筛选回到第 1 页。筛选只影响列表，不影响上方统计图（后者为近 30 天窗口，口径在页面显式说明）。「人工核对准确率」卡里的「识别错误 N 条 / 未核对 N 条」可直接点击下钻到对应筛选。
- FR-HIS-18：**记录实际病害（可选）** —— 结论为「识别错误」时，可用 38 类下拉（`作物 · 病害`，支持搜索）补一个正确答案，存 `class_id`；留空也允许。用途：把「一条错误日志」升级为「一条带真值的标注样本」，作为真实域补数据入口。判为「识别正确」或取消核对时，实际病害自动清空；若所选实际病害与预测类别相同，界面给出「这次其实是识别正确」的提醒，防止产生自相矛盾的统计样本。

### 3.6 用户管理模块（FR-USR）
- FR-USR-01：注册（邮箱/用户名+密码）。
- FR-USR-02：登录 / 登出（JWT）。
- FR-USR-03：个人信息管理（昵称、修改密码）。
- FR-USR-04：密码加盐哈希存储，HTTPS 传输。

### 3.7 界面偏好模块（FR-UI）
- FR-UI-01：个人中心提供 5 个显示开关（作物分布 / 置信度分布 / 识别趋势 / 非叶片拦截 / 人工核对准确率）+ 恢复默认。
- FR-UI-02：偏好保存在**本浏览器**（`localStorage`），刷新与重开浏览器保持，换设备回默认全显示。
- FR-UI-03：全局布局固定 —— 侧栏与顶栏不随内容滚动，仅内容区可滚；切页时内容区回到顶部。

## 4. 非功能需求（NFR）
- NFR-PERF：并发识别请求经队列/批处理，P95 推理 ≤ 500 ms。
- NFR-SEC：用户密码 bcrypt/argon2 哈希；通信 HTTPS；上传图像不用于训练外的其他用途（任务书 6.2）。
- NFR-COMPAT：响应式布局，适配 PC 与移动端浏览器。
- NFR-LIMIT：对训练集外作物/病害、复杂田间光照、枝叶遮挡、混合侵染，明确提示「建议人工复核」（任务书 6.3）。

## 5. 技术架构概述

> 架构图为矢量 SVG：`docs/assets/architecture.svg`（交付包内为 `01_需求与设计（任务1、5）/系统架构设计图.svg`）。

前后端分离 B/S 架构：
- **前端**：React 18 + Vite 5 + Ant Design 5，响应式（PC / 移动同套界面）。
- **接入**：Nginx 终止 TLS、托管前端构建产物、`/api` 反向代理；开发期用 Vite proxy。
- **后端**：FastAPI 提供 RESTful API（用户认证、预处理、推理、历史、知识查询）。
- **模型**：PyTorch ResNet18（ImageNet 预训练 + 迁移学习微调），推理服务常驻；另有独立叶片检测头用于非叶片拒识。
- **数据**：SQLite 持久化（用户、历史、病害知识、配置），WAL 模式。
- **部署**：单服务进程（uvicorn）+ Nginx + TLS；三后端（fp32 / INT8 / 剪枝）可切换。
- **运维**：`/health` 存活检查 + `/records/ood-stats` 判据分布监控，详见 `docs/13_部署运维手册.md`。

## 6. 数据说明
- 数据集：PlantVillage（本地路径 `F:\实训产品\基于CNN的农作物叶片病害识别系统\PlantVillage`），**38 类 / 54,420 张**。
- 划分：训练:验证:测试 = 8:1:1（按类分层抽样）。
- 类别不均衡显著（Orange 黄龙病 5,507 张 vs Potato healthy 152 张）→ 采用 **类别加权损失 + 数据增强**（随机旋转、水平翻转、亮度/色彩扰动）。
- 38 类映射（作物 + 中文病名）见《数据库设计文档》`disease_knowledge` 表。

## 7. 模型方案
1. 加载 ImageNet 预训练 ResNet18，替换末端全连接层为 38 分类输出。
2. 损失：加权交叉熵；优化器：Adam；早停监控验证集准确率。
3. 评估：测试集整体准确率 + 各类别 Precision/Recall/F1 + 混淆矩阵。
4. 优化（任务书 3.3）：模型量化（int8）+ 结构剪枝，降低体积与推理耗时，保留精度可接受下降。

## 8. 验收标准（GIVEN-WHEN-THEN）
- **AC-01（准确率）**：GIVEN 测试集 38 类，WHEN 模型评估，THEN 整体准确率 ≥ 85% 且每类 F1 ≥ 0.80，否则迭代调参/增广。
- **AC-02（上传）**：GIVEN 用户上传合法 jpg/png，WHEN 提交，THEN 显示预览并可触发识别；非法格式/超尺寸给出明确错误。
- **AC-03（推理）**：GIVEN 已登录用户上传叶片图，WHEN 调用推理接口，THEN 返回类别+置信度+Top-3。
- **AC-04（历史）**：GIVEN 识别完成，WHEN 用户保存，THEN 历史列表可见且可导出。
- **AC-05（安全）**：GIVEN 未登录，WHEN 访问历史/个人信息，THEN 重定向登录；密码非明文存储。
- **AC-06（免责）**：GIVEN 展示结果，THEN 页面含农技服务免责声明。
- **AC-07（作物前置）**：GIVEN 用户未选择作物，WHEN 查看识别页，THEN「开始识别」按钮禁用且可见「仅支持列表内作物」说明；选择作物后方可上传识别。
- **AC-08（历史可管理）**：GIVEN 已有一条记录，WHEN 用户改名 / 标记对错 / 删除，THEN 刷新页面后状态仍保持，且统计口径随之更新；删除后磁盘原图不残留。
- **AC-09（历史完整可见）**：GIVEN 用户有 N 条记录（N>页大小），WHEN 逐页翻取，THEN 页脚显示「共 N 条」且遍历结果无重复、无遗漏。
- **AC-10（布局固定）**：GIVEN 任意长页面，WHEN 滚动到底部，THEN 左侧菜单与顶栏位置不变，`window.scrollY` 保持 0。
- **AC-11（判卷语义）**：GIVEN 用户已知真实病害，WHEN 查看某条识别记录，THEN 可判定「识别正确 / 识别错误」而无需提交自己的答案；界面不出现「判断正确 / 判断错误」这类会被误读为「用户判断失误」的文案。
- **AC-12（筛出错样本）**：GIVEN 用户已把 3 条记录标为「识别错误」，WHEN 选择「仅识别错误」，THEN 列表只显示这 3 条、页脚「共 3 条」、徽标数字同步为 3；点击统计卡「识别错误 3 条」获得同一结果。
- **AC-13（错误样本带真值）**：GIVEN 一条记录被判为「识别错误」，WHEN 用户从 38 类中选择实际病害，THEN 列表该行显示「实际：X」、CSV 导出含「实际病害」列；若把结论改回「识别正确」或「未核对」，该字段自动清空。
- **AC-14（批量须同作物）**：GIVEN 用户在批量模式选了「番茄」并上传 3 张，WHEN 点「开始批量识别」，THEN 先弹出确认框写明「确认这 3 张都是「番茄」的叶片吗」并说明混入其他作物会被强行判成本作物病害，用户确认后才发起请求；未选作物时该按钮禁用。
- **AC-15（批量上限与部分失败）**：GIVEN 用户一次选择 10 张，WHEN 上传，THEN 只收下前 9 张并提示「一次最多识别 9 张，多出的图片已忽略」；GIVEN 9 张中有 1 张是损坏文件，WHEN 识别，THEN 其余 8 张正常出结果，失败项单独列出文件名与原因，汇总条显示「成功 8 / 失败 1」。
- **AC-16（批量结果可追查）**：GIVEN 一次 3 张的批量识别完成，WHEN 打开识别历史，THEN 新增 3 条记录、图片名为各自原始文件名；点开某张卡片可看该张 Top-3 与参考图，框选重识别后只新增 1 条裁剪记录、原记录仍在。

## 9. 范围边界
**做**：Web 端 38 类识别、Top-3 可视化、防治知识、用户体系、历史、模型量化部署。
**不做**：原生移动 App；现场诊断替代；训练集外作物/病害识别；农药电商交易；多病害像素级分割。

## 10. 风险与应对
| 风险 | 应对 |
|---|---|
| 样本不均衡致小类 F1 不达标 | 类别加权 + 强数据增强 + 小类过采样 |
| 田间泛化差（光照/遮挡/混合） | 界面明确「建议人工复核」提示；推理阈值过低时返回「不确定」 |
| 8GB 显存训练受限 | batch_size 调至 64~128；混合精度(AMP)训练 |
| 任务书 26 类 vs 数据 38 类 | 已确认按 38 类，文档统一口径 |
| 用户隐私合规 | HTTPS + 密码哈希 + 数据用途声明 |
