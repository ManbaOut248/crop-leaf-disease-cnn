# 基于 CNN 的农作物叶片病害识别系统 — 数据库设计文档

> 版本：V1.0（设计阶段 M1）｜ 数据库：SQLite（单文件 `app.db`）｜ 对应任务书 3.1

## 1. 设计约定
- 主键统一 `INTEGER PRIMARY KEY AUTOINCREMENT`。
- 时间统一 `DATETIME`（ISO8601 字符串，UTC 存储）。
- 密码相关字段只存哈希（bcrypt/argon2），不存明文。
- 字符集：UTF-8（病害中文名需正确存储）。

## 2. ER 概览
```
users 1───* records           (用户 : 识别历史)
records *───1 disease_knowledge (历史.病害编码 → 病害知识)
config  (系统配置键值对，单行/多行)
```
`disease_knowledge` 为**静态字典表**（38 类），与识别模型输出类别一一对应。

## 3. 表结构

### 3.1 users（用户表）
| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| id | INTEGER | PK | 用户ID |
| username | TEXT | UNIQUE, NOT NULL | 用户名 |
| email | TEXT | UNIQUE | 邮箱 |
| password_hash | TEXT | NOT NULL | 密码哈希 |
| nickname | TEXT | | 昵称 |
| created_at | DATETIME | NOT NULL | 注册时间 |
| updated_at | DATETIME | | 更新时间 |

索引：`CREATE UNIQUE INDEX idx_users_username ON users(username);`

### 3.2 records（识别历史表，实现表名 `recognition_records`）
| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| id | INTEGER | PK | 记录ID |
| user_id | INTEGER | FK→users.id | 所属用户 |
| image_name | TEXT | | **磁盘文件名**（`uuid.ext`），缩略图定位用，不对外展示 |
| orig_name | TEXT | | **用户上传时的原始文件名**（如 `番茄晚疫病.jpg`），历史页展示用。2026-10-29 新增；此前的行该列为 NULL，接口退化为 `历史图片 #<id>` |
| pred_class_id | INTEGER | FK→disease_knowledge.id | 预测病害编码 |
| confidence | REAL | NOT NULL | 预测置信度 0~1 |
| top3_json | TEXT | | Top-3 [{class_id, prob}] JSON。**仅内部存储**，接口对外返回解析后的 `top3` |
| custom_name | TEXT | | **用户自定义命名**（≤40 字符）。2026-10-29 新增；空串与 NULL 都表示未命名 |
| verdict | TEXT | | **人工核对结论（给 AI 判卷）**：`NULL`=未核对 / `correct`=识别正确 / `wrong`=识别错误。2026-10-29 新增 |
| verdict_at | DATETIME | | 核对时间。`verdict` 置空时同步清空，避免「未核对但有核对时间」的矛盾行 |
| ground_truth_class_id | INTEGER | | **人工确认的实际病害类别**（0~37），仅在 `verdict='wrong'` 时有意义。2026-10-29 新增；NULL=未填写。存 class_id 而非病名，类别改名后历史记录自动跟随 |
| leaf_prob / leaf_prob_source / mean_chroma / likely_not_leaf | REAL/TEXT/REAL/INTEGER | | 非叶片判据快照（运行期监控用，2026-10-19 新增） |
| created_at | DATETIME | NOT NULL | 识别时间 |

索引：`CREATE INDEX idx_records_user ON recognition_records(user_id, created_at DESC);`
另建 `idx_records_leafprob ON recognition_records(created_at DESC, leaf_prob)` 供 OOD 聚合查询。

> 为什么把「磁盘名」和「展示名」分成两列：`image_name` 落的是 uuid（防重名、防路径穿越），
> 直接展示给用户就是 `9f3c…a1.jpg`，看不出是哪张图；而重命名磁盘文件会破坏已有记录的
> 缩略图定位，故只能新增一列存原始文件名。
>
> 为什么自定义命名要单独一列而不是覆盖 `orig_name`：原始文件名是「这张图从哪来」的唯一
> 线索，覆盖掉就再也认不出来了；展示时按 `custom_name → orig_name → 历史图片 #id` 三级回落。
>
> 为什么 `verdict` 不由模型自己算：闭集模型对体系外作物、健康叶也会给高置信度错误答案
> （`docs/25` 实测未知作物 88.2% 硬答），只有人能提供真值。这一列也是后续补真实域标注的入口。
>
> 为什么 `verdict` 存 `correct/wrong` 而界面上写「识别正确 / 识别错误」：存的是**对被评价对象的
> 判断**（AI 的输出对不对），枚举名保持短小稳定，展示层负责消除歧义。语义上用户是拿着已知
> 真实病害来判卷的人，**不提交自己的答案**，所以 `ground_truth_class_id` 允许为 NULL。
>
> 为什么 `ground_truth_class_id` 与 `verdict` 绑定清理：结论改成 `correct` 或置 NULL 时，
> 若调用方没有显式给出实际病害，该列会被一并置空（见 `db.update_record`）。否则会留下
> 「已判定识别正确，却写着实际病害是别的」的自相矛盾行，统计时还得额外加条件过滤。

## 4. 建表 SQL（节选）
```sql
CREATE TABLE users (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  username TEXT UNIQUE NOT NULL,
  email TEXT UNIQUE,
  password_hash TEXT NOT NULL,
  nickname TEXT,
  created_at DATETIME NOT NULL,
  updated_at DATETIME
);
CREATE TABLE records (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  user_id INTEGER NOT NULL REFERENCES users(id) ON DELETE CASCADE,
  image_path TEXT NOT NULL,
  pred_class_id INTEGER NOT NULL REFERENCES disease_knowledge(id),
  confidence REAL NOT NULL,
  top3_json TEXT,
  created_at DATETIME NOT NULL
);
CREATE INDEX idx_records_user ON records(user_id, created_at DESC);
CREATE TABLE disease_knowledge (
  id INTEGER PRIMARY KEY,
  crop_en TEXT NOT NULL,
  crop_cn TEXT NOT NULL,
  disease_en TEXT,
  disease_cn TEXT NOT NULL,
  is_healthy INTEGER NOT NULL,
  symptom TEXT,
  control TEXT
);
CREATE TABLE config (
  key TEXT PRIMARY KEY,
  value TEXT,
  updated_at DATETIME
);
```

## 5. 数据隐私（对齐任务书 6.2）
- 上传原图存于服务端受控目录，文件名随机化，禁止暴露用户目录结构。
- `records.image_path` 仅存服务端相对路径。
- 数据库文件受限访问；可选整库加密（SQLCipher）。
- 明确告知：图像仅用于本次识别，不作训练外用途。
