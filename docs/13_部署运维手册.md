# 部署运维手册

> 对应任务书：第 8 项「系统集成与联调 → 部署文档」、5.2「部署运维手册」、6.2「HTTPS 加密传输 + 数据库存储加密」。
> 适用版本：本项目当前 `main` 分支。所有命令均在 **Windows CMD** 下验证通过，Linux 差异单独标注。

## 0. 一页速查

| 事项 | 值 |
|---|---|
| 后端 | FastAPI + Uvicorn，默认 `127.0.0.1:8000` |
| 前端 | React + Vite，开发 `5173`，生产由 Nginx 托管 `dist/` |
| 数据库 | SQLite（WAL 模式），`data/app.db` |
| 上传目录 | `data/uploads/` |
| 模型目录 | `models/`（权重不入库，需单独获取或重训） |
| 健康检查 | `GET /api/v1/health` → `{"data":{"status":"up"}}` |
| 运维指标 | `GET /api/v1/records/ood-stats?days=7`（需登录） |
| 证书目录 | `certs/`（**已 gitignore，私钥绝不入库**） |

**后端启动命令（记住三个参数，缺一不可）**

```cmd
py -3.12 -m uvicorn src.api.main:app --host 127.0.0.1 --port 8000 --no-proxy-headers
```

| 参数 | 为什么不能省 |
|---|---|
| `py -3.12` | 宿主机 `python` 可能是 3.13，而 torch 2.5.1 装在 3.12 环境里 |
| `--host 127.0.0.1` | 只监听本机，外部一律经 Nginx 进来；直接监听 `0.0.0.0` 会绕过 TLS |
| `--no-proxy-headers` | **uvicorn 默认信任 127.0.0.1 的 `X-Forwarded-For` 并在应用层之前改写客户端 IP**，导致接口限流可被一行请求头绕过（实测 65 次请求全程未拦）。安全审计 P1 项 |

## 1. 环境要求

### 1.1 软件

| 组件 | 版本 | 说明 |
|---|---|---|
| Python | **3.12.x** | 3.13 上 torch 2.5.1 未必有轮子 |
| Node.js | ≥ 18（推荐 20/22） | 仅前端构建需要 |
| Nginx | ≥ 1.20 | 生产反向代理 + TLS 终止（可选，见 §4） |
| 操作系统 | Windows 10/11 或 Linux | 本文以 Windows 为主 |

### 1.2 硬件

| 场景 | 建议 |
|---|---|
| 推理（CPU） | 4 核 / 8GB，单张 224×224 前向约 20~60ms |
| 推理（GPU） | 显存 ≥ 2GB 即可（ResNet18 很小） |
| 前端构建 | 2GB 内存足够（约 3100 个模块） |

### 1.3 目录与端口

```
项目根/
├─ src/api/          后端
├─ src/model/        模型与推理
├─ src/web/          前端（dist/ 为构建产物）
├─ data/             app.db、uploads/、split/
├─ models/           *.pth / *.pt / ood_head.npz（不入库）
├─ certs/            TLS 证书与私钥（不入库）
├─ deploy/           nginx.conf.example
└─ rag/              RAG 语料库与提示词（可选组件）
```

| 端口 | 用途 | 是否对外 |
|---|---|---|
| 8000 | 后端 API | 否（只给 Nginx 转发） |
| 8443 | 后端直连 TLS（可选形态） | 视部署形态 |
| 5173 | 前端开发服务器 | 仅开发 |
| 80 / 443 | Nginx | 是 |

## 2. 首次部署

### 2.1 获取代码与依赖

```cmd
cd /d "F:\WorkBuddy工作空间\基于CNN的农作物叶片病害识别系统"
py -3.12 -m pip install -r requirements.txt
cd src\web
npm ci
cd ..\..
```

### 2.2 准备模型权重（不入库，必须单独获取）

仓库不含权重（`models/*.pth|*.pt|*.npz` 已忽略）。二选一：

**A. 从训练产物拷贝**（有原始环境时）

```
models\best_resnet18_38.pth          # 38 类主模型（必需）
models\pruned_resnet18_38.pth        # 剪枝版（可选）
models\quantized_resnet18_38.pt      # INT8 版（可选）
models\ood_head.npz                  # 叶片检测头（强烈建议）
```

**B. 重新训练 / 重建**

```cmd
py -3.12 -m src.model.train
py -3.12 scripts/train_ood_head.py
```

> 缺 `ood_head.npz` 时服务仍可启动，但会回退到 MSP 判据并打印告警：
> 真实田间照片误杀率会从约 5% 恶化到 50% 以上。生产务必带上。

### 2.3 生成并固定密钥（两把，性质不同）

| 密钥 | 缺失时行为 | 影响 |
|---|---|---|
| `JWT_SECRET` | 每次启动**随机生成** | 服务可用，但**重启后所有人需重新登录** |
| `DB_FIELD_KEY` | **不启用**字段加密 + 告警 | email 明文落库 |

```cmd
py -3.12 -c "import secrets;print(secrets.token_urlsafe(48))"
```
复制输出，然后：

```cmd
set JWT_SECRET=这里粘贴上一步的输出
```

```cmd
py -3.12 -c "from cryptography.fernet import Fernet;print(Fernet.generate_key().decode())"
```
复制输出（44 字符），然后：

```cmd
set DB_FIELD_KEY=这里粘贴上一步的输出
```

> **`DB_FIELD_KEY` 必须长期保持不变。** 它是数据解密密钥，丢了就解不开历史 email；
> 与 `JWT_SECRET` 不同，它**不能**随机重建。请与数据库备份分开保管（见 §7）。

生产建议把这两行写进一个**不入库的启动脚本**（如 `run_server.cmd`），或使用系统的服务管理器注入环境变量。

### 2.4 初始化数据库

首次启动会自动建表并导入 38 类知识库，无需手工操作。启动后可确认：

```cmd
py -3.12 -c "import sqlite3;c=sqlite3.connect('data/app.db');print([r[1] for r in c.execute('PRAGMA table_info(recognition_records)')])"
```

应包含 `leaf_prob / leaf_prob_source / mean_chroma / likely_not_leaf` 四列（OOD 监控列，旧库启动时会自动 `ALTER TABLE` 补齐）。

### 2.5 首次启动与自检

```cmd
py -3.12 -m uvicorn src.api.main:app --host 127.0.0.1 --port 8000 --no-proxy-headers
```

另开窗口：

```cmd
curl http://127.0.0.1:8000/api/v1/health
```

预期返回 `{"code":0,"data":{"status":"up",...}}`。

首次调用 `/api/v1/predict` 会加载权重（数秒），之后常驻内存。

## 3. 部署形态

### 形态 A：单机 + 反向代理（推荐）

```
浏览器 --HTTPS(443)--> Nginx --HTTP(127.0.0.1:8000)--> uvicorn
                        └── 同时托管前端 dist/
```

优点：证书只在一处管理、可加缓存与压缩、后端不需暴露。

**步骤**

1. 构建前端：

```cmd
cd src\web
npm run build
cd ..\..
```

2. 生成证书（内网/验收用自签；有域名用 Let's Encrypt）：

```cmd
py -3.12 scripts/gen_selfsigned_cert.py
```

3. 拷贝并修改 `deploy/nginx.conf.example` 中三处：`server_name`、证书路径、前端 `root`。

4. 后端以 **`TRUST_PROXY=1`** 启动（让限流按 `X-Forwarded-For` 取真实来源）：

```cmd
set TRUST_PROXY=1
set REQUIRE_HTTPS=1
py -3.12 -m uvicorn src.api.main:app --host 127.0.0.1 --port 8000 --no-proxy-headers
```

> `TRUST_PROXY=1` 与 `--no-proxy-headers` **必须成对**：
> 前者让应用层读转发头，后者阻止 uvicorn 抢先改写，否则两层同时改写会导致口径混乱。
> 只有在**确实位于可信代理之后**才开 `TRUST_PROXY`，否则客户端可伪造 IP 绕过限流。

5. 启动 Nginx 并验证：

```cmd
curl -k https://localhost/api/v1/health
```

### 形态 B：应用直连 TLS（无代理，小规模）

```cmd
py -3.12 -m uvicorn src.api.main:app --host 0.0.0.0 --port 8443 --ssl-keyfile certs/dev-key.pem --ssl-certfile certs/dev-cert.pem --no-proxy-headers
```

此时 `REQUIRE_HTTPS=1` 会让 HTTP 请求 308 跳转到 HTTPS，并在 HTTPS 响应上加 HSTS。

> 自签证书浏览器会告警（需手动信任），**仅用于内网验收**。

### 形态 C：纯内网演示（不加密）

```cmd
py -3.12 -m uvicorn src.api.main:app --host 127.0.0.1 --port 8000 --no-proxy-headers
cd src\web && npm run dev
```

访问 `http://127.0.0.1:5173`。**仅限本机演示**，不得用于真实用户数据。

## 4. 服务托管（开机自启）

### 4.1 Windows（NSSM）

```cmd
nssm install LeafDisease "C:\Windows\System32\cmd.exe" "/c py -3.12 -m uvicorn src.api.main:app --host 127.0.0.1 --port 8000 --no-proxy-headers"
nssm set LeafDisease AppDirectory "F:\WorkBuddy工作空间\基于CNN的农作物叶片病害识别系统"
nssm set LeafDisease AppEnvironmentExtra JWT_SECRET=你的值 DB_FIELD_KEY=你的值 TRUST_PROXY=1 REQUIRE_HTTPS=1
nssm set LeafDisease Start SERVICE_AUTO_START
nssm start LeafDisease
```

> `AppEnvironmentExtra` 里空格分隔多个键值，值含特殊字符时改用 `nssm edit` 图形界面填写。

### 4.2 Linux（systemd）

```ini
# /etc/systemd/system/leafdisease.service
[Unit]
Description=Leaf Disease Recognition API
After=network.target

[Service]
Type=simple
User=www-data
WorkingDirectory=/opt/leafdisease
Environment="JWT_SECRET=..."
Environment="DB_FIELD_KEY=..."
Environment="TRUST_PROXY=1"
Environment="REQUIRE_HTTPS=1"
ExecStart=/usr/bin/python3.12 -m uvicorn src.api.main:app --host 127.0.0.1 --port 8000 --no-proxy-headers
Restart=on-failure
RestartSec=5

[Install]
WantedBy=multi-user.target
```

```bash
sudo systemctl daemon-reload && sudo systemctl enable --now leafdisease
```

> **不要用多 worker**（`--workers N`）。限流是进程内字典、模型也按进程常驻，
> 多 worker 会让限流各自计数、显存翻倍。需要横向扩展时应先把限流换成 Redis。

## 5. 配置项总表（环境变量）

| 变量 | 默认 | 作用 | 生产建议 |
|---|---|---|---|
| `JWT_SECRET` | 每次启动随机 | JWT 签名密钥 | **必须固定设置** |
| `JWT_EXPIRE_DAYS` | `7` | token 有效期（天） | 1~7 |
| `DB_FIELD_KEY` | 空（不加密） | PII 字段加密密钥 | **必须固定设置** |
| `DATA_ROOT` | 内置数据集路径 | PlantVillage 根目录 | 仅训练/评测需要 |
| `TRUST_PROXY` | `0` | 是否信任 `X-Forwarded-For` / `X-Forwarded-Proto` | 有 Nginx 时设 `1` |
| `REQUIRE_HTTPS` | `0` | 强制 HTTPS + HSTS | 对外服务设 `1` |
| `HSTS_MAX_AGE` | `31536000` | HSTS 有效期（秒） | 先用 `300` 试运行 |
| `TLS_CERT` / `TLS_KEY` | 空 | 应用直连 TLS 的证书路径 | 形态 B 才用 |
| `OOD_HEAD_ENABLE` | `1` | 是否启用叶片检测头 | 保持 `1` |
| `OOD_HEAD_THRESHOLD` | `0.5` | 检测头判定阈值 | 误杀多则调低（如 0.4） |
| `OOD_MSP_THRESHOLD` | `0.98` | 回退判据阈值（检测头不可用时） | 一般不动 |
| `OOD_CHROMA_THRESHOLD` | `8.0` | 灰阶判定阈值（仅影响提示文案） | 一般不动 |
| `CORS_ORIGINS` | `localhost:5173,3000` | 允许的前端源，逗号分隔 | 改成实际域名 |
| `CORS_ALLOW_CREDENTIALS` | `false` | 是否允许带 cookie 的跨域 | 本项目用 Bearer，保持 `false` |

## 6. 日志

| 来源 | 位置 | 说明 |
|---|---|---|
| Uvicorn / 应用 | 标准输出 | 生产由 NSSM/systemd 收集，建议重定向到文件 |
| 识别失败 | `logging.getLogger("uvicorn.error")` | 500 只回传通用文案，详细异常仅在此处可见 |

重定向示例：

```cmd
py -3.12 -m uvicorn src.api.main:app --host 127.0.0.1 --port 8000 --no-proxy-headers >> logs\api.log 2>&1
```

Linux 用 logrotate（`/etc/logrotate.d/leafdisease`）：

```
/var/log/leafdisease/*.log {
    daily
    rotate 14
    compress
    missingok
    notifempty
    copytruncate
}
```

> `copytruncate` 不能用 `create` 代替：uvicorn 持有文件句柄，改名后仍写旧 inode。

## 7. 备份与恢复

### 7.1 必须备份的三样

| 对象 | 原因 |
|---|---|
| `data/app.db`（含 `-wal`、`-shm`） | 用户、历史、监控数据 |
| `data/uploads/` | 用户上传原图（历史记录回看依赖） |
| `DB_FIELD_KEY` | **丢了就解不开 email**，且它不在备份文件里 |

`models/` 不必备份（可重训重建），但**备份能省下几小时**，视磁盘决定。

### 7.2 在线备份（WAL 模式下不能直接 copy 单个文件）

```cmd
py -3.12 -c "import sqlite3;s=sqlite3.connect('data/app.db');d=sqlite3.connect('backup/app-%DATE%.db');s.backup(d);d.close();s.close();print('ok')"
```

> 直接 `copy data\app.db` 在 WAL 模式下会漏掉未 checkpoint 的事务，可能备份出一个缺数据的库。
> `sqlite3.backup()` 会加锁并生成一致快照。

配合 `robocopy` 备份上传目录：

```cmd
robocopy data\uploads backup\uploads /E /XO /R:2 /W:2
```

### 7.3 恢复

1. 停服务（避免半写状态）；
2. 还原 `app.db` 与 `uploads/`；
3. **确保 `DB_FIELD_KEY` 与备份时一致**，否则 email 列解不开（接口会返回 `null` 而不是报错）；
4. 启动，验证 `/health` 与历史列表。

### 7.4 定期任务建议

| 频率 | 动作 |
|---|---|
| 每日 | 数据库 + uploads 增量备份 |
| 每周 | 校验备份可打开（`PRAGMA integrity_check`） |
| 每次变更前 | 全量备份（本项目约定：改动前存 `backups/YYYY-MM-DD-pre-<事项>/`） |

## 8. 监控

### 8.1 存活与就绪

```cmd
curl http://127.0.0.1:8000/api/v1/health
```

返回 200 且 `status=up` 即为存活。**注意**：健康检查不加载模型，模型是否可用要看一次真实识别。

### 8.2 业务指标（`/records/ood-stats`）

```cmd
curl "http://127.0.0.1:8000/api/v1/records/ood-stats?days=7" -H "Authorization: Bearer %TOKEN%"
```

| 指标 | 关注阈值 | 异常含义 |
|---|---|---|
| `flagged_ratio` | 突增 >2 倍 | 用户在传非叶片图片，或判据退化 |
| `low_leaf_ratio` | 持续 >0.3 | 输入分布偏离训练集，需重标阈值或补数据 |
| `msp_fallback` | **>0** | 检测头未生效（如切了量化后端、缺 `ood_head.npz`）→ 真实场景误杀率会显著上升 |

> 比例的分母是 `monitored`（有判据快照的记录数），历史 NULL 行不计入——
> 用 `total` 作分母会被稀释成"一切正常"。

### 8.3 建议采集的系统指标

进程 CPU/内存、`data/` 磁盘占用（上传文件无自动清理，需按 §9.2 处理）、
请求 P95 延迟、5xx 速率。

## 9. 日常运维

### 9.1 升级

```cmd
git pull
py -3.12 -m pip install -r requirements.txt
py -3.12 -m pytest -q                      :: 回归
cd src\web && npm ci && npm run build && cd ..\..
:: 重启服务（NSSM）
nssm restart LeafDisease
curl http://127.0.0.1:8000/api/v1/health
```

数据库结构变更（如新增监控列）会在启动时自动迁移，**幂等**，可重复执行。

### 9.2 磁盘空间（已知问题）

匿名上传的文件写盘后不建立记录，也**没有自动清理**。当前实现下会缓慢增长。

手工清理孤儿文件（**先确认无记录引用，再删除**）：

```cmd
py -3.12 -c "import sqlite3,os,time,pathlib;d=sqlite3.connect('data/app.db');names={r[0] for r in d.execute('SELECT image_name FROM recognition_records')};p=pathlib.Path('data/uploads');n=0;[ (f.unlink(), globals().__setitem__('n',n+1)) for f in p.iterdir() if f.name not in names and time.time()-f.stat().st_mtime>86400 ];print('已清理',n,'个孤儿文件')"
```

> 上面这条是**一次性手工命令**，正式方案应在服务内加定时任务（审计报告第四节已列为待办）。

### 9.3 修改密钥

| 场景 | 后果 | 步骤 |
|---|---|---|
| 轮换 `JWT_SECRET` | 所有用户需重新登录（token 失效） | 改环境变量 → 重启 |
| 更换 `DB_FIELD_KEY` | **历史 email 全部无法解密** | **不要直接换**。需先写迁移脚本：用旧密钥读出 → 用新密钥写回 |

### 9.4 切换推理后端

`src/config.py` 的 `INFER_BACKEND` 可选 `fp32`（默认）/ `quantized` / `pruned`。

> ⚠️ **切到 quantized / pruned 会静默关闭叶片检测头**（特征分布不同），
> 判据回退到 MSP，真实场景误杀率显著上升。启动日志会打印告警，
> 切换后应检查 `/records/ood-stats` 的 `msp_fallback` 是否 >0。

## 11. 故障排查

| 现象 | 可能原因 | 处理 |
|---|---|---|
| 启动报 `No module named 'torch'` | 用错 Python | 改用 `py -3.12` |
| 端口被占用（`WinError 10048`） | 旧进程未退 | `netstat -ano \| findstr :8000` → `taskkill /PID 进程号 /F` |
| 接口 429 | 触发限流（60 次/分/IP） | 正常行为；若误伤，检查是否 `TRUST_PROXY` 配错导致所有人共用一个 IP |
| 伪造 `X-Forwarded-For` 能绕过限流 | 少了 `--no-proxy-headers`，或 `TRUST_PROXY` 该开没开 | 按 §0 表格核对 |
| `/predict` 返回 503「模型尚未就绪」 | `models/best_resnet18_38.pth` 缺失 | 按 §2.2 准备权重 |
| 识别结果页空白 / 前端白屏 | 前后端字段契约不一致（历史上发生过两次） | 打开浏览器控制台看报错；按 `docs/04_API接口文档.md` 核对字段名 |
| 重启后所有人被踢下线 | `JWT_SECRET` 未固定，每次启动随机 | 按 §2.3 固定 |
| 历史记录里 email 显示为 `null` | `DB_FIELD_KEY` 与数据加密时不一致 | 找回原密钥；不可用新密钥硬换 |
| `curl -k https://` 报证书不匹配 | 证书 SAN 不含该地址 | 重新生成并确保 SAN 含实际访问的域名/IP |
| 浏览器提示「不是私密连接」 | 自签证书 | 内网验收可手动信任；对外应换正式证书 |
| 上传大图报 500 / 解压炸弹 | 图片像素超限（Pillow 上限 5000 万） | 属预期防护，提示用户压缩后重传 |
| 移动端菜单按钮遮挡标题 | 曾是 AntD 零宽侧栏的定位问题 | 已在 `index.css` 用双类选择器修正（单类会被运行时注入的样式覆盖） |
| 前端 `npm run build` 报 `emptyDir` | 目标目录被占用 | 关闭占用进程，或改 `--outDir` 到新目录 |
