## 一、要回答的三个问题

1. 之前混合微调在真实域上的增益，有多少是「番茄留出图泄漏」造成的？
2. 给真实域样本 4 倍损失权重，能否在干净切分上进一步提升？
3. 新训的权重能不能替换当前部署权重？

## 三、实验设计：一次重训，只改一个变量

### 3.1 第 0 层 A 方案 · 防泄漏切分

问题背景：旧混合索引 `dataset_index_mixed.json` 把 677 张番茄真实图**全部**放进训练集；
而评估集里的 120 张正是从这 677 张里留出来的 —— 等于模型在考试前看过答案。

做法（`scripts/split_tomato_holdout.py`，seed=42 分层）：

```
677 张番茄真实图
  ├── 120 张 → 从训练集剔除，只进评估集（data/real_mix/ 下，路径未搬）
  └── 557 张 → 留在训练集
评估集 = 原 realtest 225 张（番茄 66）+ 新留出 120 张 = 345 张（番茄 186）
```

产物：`dataset_index_mixed_v2.json`（训练 46,371）、`dataset_index_realtest_v2.json`（345）。
清单：`outputs/index/tomato_holdout_manifest.json`。

> ⚠️ 注意 120 张留出图的**文件路径仍在 `data/real_mix/`**，没有复制到别处，
> 只是从训练索引里删掉了。所以事后想区分「泄漏/未泄漏」，判据是目录前缀
> （`real_mix_test/` = 未泄漏 66 张，`real_mix/` = 留出 120 张），**不能用文件名匹配** ——
> 两个目录里有 12 个文件名撞车，会把 120 张误算成 132 张。

### 3.2 第 1 层 · 真实域 4 倍权重

没有改 `compute_class_weights()` 的类权重公式，而是在其之上叠加**样本级**权重：

```python
# scripts/finetune_domain.py
# 损失 = Σ(w_i · ce_i) / Σ(w_i)，其中 w_i = class_weight[label_i] × sample_weight_i
# sample_weight：PV 样本 = 1.0，真实域样本 = REAL_DOMAIN_WEIGHT（默认 1.0 = 旧行为）
ce = F.cross_entropy(out, labels, reduction="none")
w = class_weight[labels] * sw
loss = (ce * w).sum() / w.sum()
```

为什么不用类权重：番茄在 PlantVillage 里有 14,537 张，类权重被压到约 0.078；真实域番茄图
也被同样压低，而它恰恰是唯一能教会模型「田间长什么样」的信号。类权重无法区分
同类的 PV 图和真实图，样本级权重可以。

归一化分母必须是**权重之和**而不是 batch 样本数 —— PyTorch 的
`CrossEntropyLoss(weight=w, reduction='mean')` 内部就是除以目标类权重之和
（实测 4.2085 = Σ(w·ce)/Σ(w)，而非 Σ(w·ce)/N = 13.17）。写错会让 A/B 不只差一个变量。

### 3.3 两组配置（除权重系数外完全一致）

| 项 | ctrl | w4 |
|---|---|---|
| `REAL_DOMAIN_WEIGHT` | 1.0 | **4.0** |
| 损失占比 | 4.1% | **14.6%** |
| 起点 | `backups/2026-10-20-pre-finetune/models/best_resnet18_38.pth`（纯 PV，epoch 24，val_f1 0.9943） | 同左 |
| 训练集 | 46,371（PV 44,470 + 真实域 1,901） | 同左 |
| 轮数 / LR / batch | 10 / 5e-5 余弦退火 / 64 AMP | 同左 |
| 早停 | 综合分数 = PV_F1 + 0.5×REAL_val，PATIENCE=6 | 同左 |

起点必须用**纯 PV 基座**，不能用 `models/best_resnet18_38.pth` —— 后者已是 epoch 6 微调后的权重
（含真实域信息），拿来当起点会二次污染留出集。

### 4.1 McNemar 配对检验

同一批图上的配对比较，用精确二项检验（`scipy.stats.binomtest`）：

| 对比 | 番茄 186 张 | 独对（A/B） | p | 判定 |
|---|---|---:|---:|---|
| w4 vs 纯 PV 基座 | 45.2% vs 26.3%（+18.8pp） | 55 / 20 | 0.0001 | ✅ 显著 |
| ctrl vs 纯 PV 基座 | 40.3% vs 26.3%（+14.0pp） | 47 / 21 | 0.0022 | ✅ 显著 |
| **w4 vs ctrl** | **45.2% vs 40.3%（+4.8pp）** | **19 / 10** | **0.1360** | ⚠️ 不显著 |
| w4 vs 当前部署 | 45.2% vs 48.4%（−3.2pp） | 14 / 20 | 0.3915 | ⚠️ 不显著 |

整体 345 张口径：

| 对比 | 差异 | p | 判定 |
|---|---:|---:|---|
| w4 vs 纯 PV 基座 | +22.0pp | <0.0001 | ✅ 显著 |
| ctrl vs 纯 PV 基座 | +18.8pp | <0.0001 | ✅ 显著 |
| w4 vs ctrl | +3.2pp | 0.0708 | ⚠️ 不显著 |
| w4 vs 当前部署 | −0.9pp | 0.7493 | ⚠️ 不显著 |

### 4.2 逐类变化（w4 vs ctrl，番茄内部有分化）

| 类 | ctrl → w4 | Δ | n |
|---|---|---:|---:|
| Tomato___healthy | 5 → 9 | +4 | 18 |
| Tomato___Septoria_leaf_spot | 15 → 19 | +4 | 35 |
| Tomato___Late_blight | 16 → 20 | +4 | 28 |
| Tomato___Tomato_Yellow_Leaf_Curl_Virus | 0 → 2 | +2 | 17 |
| Tomato___Bacterial_spot | 6 → 5 | −1 | 26 |
| Tomato___Early_blight | 14 → 10 | **−4** | 23 |

**读法**：加权让「样本量足」的类受益（Septoria 35 张、Late_blight 28 张），
却让 Early_blight 掉了 4 张 —— 后者的真实域训练样本本来就少，4 倍权重把它从
「被忽略」推到「过拟合」那一侧了。逐作物维度上 12 个作物**无一变差**：
番茄 +4.8pp、Pepper +5.9pp、Corn +4.3pp，其余持平。

## 五、泄漏拆分：48.4% 里有多少水分

把 186 张番茄按「部署权重训练时有没有见过」切开：

| 权重 | 番茄合计 | 已泄漏 120 张 | 未泄漏 66 张 |
|---|---:|---:|---:|
| 纯 PV 基座 | 49/186（26.3%） | 36/120（30.0%） | 13/66（19.7%） |
| 当前部署权重 | 90/186（48.4%） | **61/120（50.8%）** | 29/66（43.9%） |
| ctrl（w=1.0） | 75/186（40.3%） | 47/120（39.2%） | 28/66（42.4%） |
| **w4（w=4.0）** | 84/186（45.2%） | 53/120（44.2%） | **31/66（47.0%）** |

未泄漏 66 张上的配对检验：

| 对比 | 准确率 | 净增 | p | 判定 |
|---|---|---:|---:|---|
| w4 vs 当前部署 | 47.0% vs 43.9% | +2 张 | 0.8036 | ⚠️ 不显著 |
| w4 vs ctrl | 47.0% vs 42.4% | +3 张 | 0.5078 | ⚠️ 不显著 |
| w4 vs 纯 PV 基座 | 47.0% vs 19.7% | +18 张 | 0.0009 | ✅ 显著 |

**这张表是本次实验最重要的产出**：

- 部署权重的 48.4% 里有约 **6.6pp 是记忆加成**（50.8% vs w4 的 44.2%）；
- 剥掉这部分后，它在 66 张真新图上是 **43.9%**，低于 w4 的 **47.0%**；
- 所以「w4 总分比部署低 3.2pp」不是退步，而是**它不再享受那 120 张的红利**。

## 七、工程记录

### 7.1 训练提速 2.4 倍

`NUM_WORKERS` 从 4 提到 10（16 核机器），并开启 `persistent_workers` + `prefetch_factor=4`：

| 阶段 | 单轮耗时 |
|---|---|
| 首轮（worker spawn + 冷缓存） | 531 s |
| 后续轮次（ctrl） | 128~145 s |
| 后续轮次（w4，缓存更热） | 74~86 s |

单组总耗时约 23~29 分钟，两组约 52 分钟。原 4 workers 配置是 5.8 分钟/轮。
覆盖方式：环境变量 `FINETUNE_WORKERS`，不动全局 `config.NUM_WORKERS`（训练/推理共用）。

### 7.2 日志全缓冲坑（已修）

10-26 那次 ctrl 组跑了 51 分钟被中止，日志 290 行**全是** `JWT_SECRET 未设置` 的 warning，
零进度行。原因：`print` 重定向到文件时走全缓冲，进程被 kill 时缓冲区没 flush；
stderr 的 warning 无缓冲，逐行落盘，把日志占满了。

修复：`main()` 开头 `sys.stdout.reconfigure(line_buffering=True)`，外部再加 `python -u` 双保险。

## 八、局限与下一步

1. **4 倍权重未达统计显著**。若要坐实，需要把评估集扩到 400+ 张番茄（当前 186 张，
   检出 5pp 效应所需样本量约 400~500）。或者直接试 8 倍权重拉开效应量。
2. **只能扫一个点**。本次只测了 1.0 和 4.0，中间的最优值未知；但每加一组要 25 分钟，
   且评估集功效不足，不值得继续盲扫。
3. **真实域训练数据仍是瓶颈**：1,901 张 / 9 类，Target_Spot 为 0 张、红蜘蛛 2 张。
   权重调整只能重分配注意力，变不出新信息。
4. **未泄漏子集只有 66 张**，任何单次对比的置信区间都很宽（43.9% 的 95%CI 约 ±12pp）。

## 九、复现命令

```bash
# 1) 重新生成防泄漏切分（幂等，seed=42）
python -m scripts.split_tomato_holdout

# 2) 两组训练（除 REAL_DOMAIN_WEIGHT 外完全一致）
BASE=backups/2026-10-20-pre-finetune/models/best_resnet18_38.pth
FINETUNE_INIT=$BASE FINETUNE_INDEX=dataset_index_mixed_v2.json \
  FINETUNE_REALTEST=dataset_index_realtest_v2.json \
  REAL_DOMAIN_WEIGHT=1.0 FINETUNE_OUT=finetuned_v2_ctrl.pth \
  FINETUNE_EPOCHS=10 FINETUNE_WORKERS=10 python -u -m scripts.finetune_domain

FINETUNE_INIT=$BASE FINETUNE_INDEX=dataset_index_mixed_v2.json \
  FINETUNE_REALTEST=dataset_index_realtest_v2.json \
  REAL_DOMAIN_WEIGHT=4.0 FINETUNE_OUT=finetuned_v2_w4.pth \
  FINETUNE_EPOCHS=10 FINETUNE_WORKERS=10 python -u -m scripts.finetune_domain

# 3) 逐图评估 + 配对检验
python -m scripts.eval_v2_ab --weights models/finetuned_v2_ctrl.pth --out backups/v2_ctrl.json
python -m scripts.eval_v2_ab --weights models/finetuned_v2_w4.pth   --out backups/v2_w4.json
python -m scripts.compare_v2_ab backups/v2_w4.json backups/v2_ctrl.json

# 4) 泄漏拆分 + 实验室域守门
python scripts/analyze_tomato_leak.py
python scripts/eval_pv_test.py models/finetuned_v2_w4.pth models/best_resnet18_38.pth
```
