# 20. 识别历史页图表功能（设计与实现）

> 2026-10-26 ｜ 起因：历史页只有表格，用户看不到自己的识别结构；`/records/ood-stats` 后端早已实现却从未被前端调用。

## 一、最终形态

历史页表格上方新增「1 组概览 + 3 张图 + 1 个运维卡」：

| 模块 | 内容 | 数据字段 |
|---|---|---|
| 概览数字卡 ×4 | 累计识别 / 涉及作物 / 平均置信度 / 需人工复核 | `total`、`crops.length`、`avg_confidence`、`need_review` |
| 作物分布 | 横向柱状，按条数降序，最多 8 种 | `crops[]` |
| 置信度分布 | 竖向柱状，6 档固定分桶 | `confidence_buckets[]` |
| 近 30 天识别量 | 竖向柱状，无记录日期补零 | `daily[]` |
| 非叶片拦截 | 拦截率 + MSP 回退 + 平均叶片概率 | `ood` |

实测（demo 账号 180 条记录）：累计 180 次、10 种作物、平均置信度 89.2%、需复核 17 条；
番茄 111 条占 62%，置信度 90-100% 占 107 条，OOD 拦截 12/160 = 7.5%。

截图：`outputs/chart_shots/01_history_top.png`、`02_history_full.png`。

## 二、为什么图表不能前端算

`/records` 的分页 `size` 上限是 100（见 `main.py` 的 `records()`）。
前端如果拉列表自己 reduce：

1. **分母错了**：记录 180 条只拿到 100 条，比例全部失真，且**不报错**——最危险的一类 bug；
2. 要发 4 个请求，每个请求的窗口/口径可能不一致；
3. 记录变多后接口变慢（100 条带 base64 缩略图）。

因此新增 `GET /stats/overview?days=30`，后端一次聚合全部图表数据（详见 `docs/04` 2.5 节）。

## 三、口径警示（最容易踩的坑）

`recognition_records.confidence` 存的是**原始 softmax**，不是温度校准值。
而页面上「可靠性 high/medium/low」标签用的是**校准后**置信度，阈值是
`calibration_domain.json` 的 `reliability_high=0.55` / `medium=0.25`（数值很低，
因为真实域校准后置信度普遍被压低）。

如果把 0.55 / 0.25 套到原始置信度上，几乎全部记录都会落进 high 档，图就没有信息量；
反过来把 0.9 / 0.7 套到校准值上，又几乎全是 low。

**处理方式**：
- 图表只画原始分布，**不给 high/medium/low 分档**；
- 副标题明确写「原始 softmax 值，未做温度校准」；
- 低于 0.5（复核线）的那一桶用警示色，语义是「这些不该轻信」，不是「可靠性 low」。

## 四、技术选型

| 方案 | 决策 |
|---|---|
| 图表库 | **echarts 5.5**，按需引入（core + BarChart + Grid/Tooltip/AxisPointer） |
| 渲染器 | **SVG**（数据量最多几十根柱，矢量缩放不糊，导出图片更清晰） |
| 封装 | `src/web/src/components/ChartCard.jsx`，统一标题/副标题/空态/高度/生命周期 |
| 色板 | 复用 AntD token：`#24814A` 主色、`#2E9E5B` 亮色、`#F2A93B` 警示、`#D6453E` 错误，**不引入第二套色板** |

按需引入的原因：整包 `import 'echarts'` 约 1 MB（gzip 330 KB），按需后只为实际用到的模块付体积。

`ChartCard` 里做了三件容易漏的事：
1. `ResizeObserver` 监听容器宽度（侧边栏折叠、窗口缩放、栅格换行都会变）；
2. 卸载时 `dispose()`，否则反复进出页面会累积实例；
3. `option` 存 ref，只 `setOption` 不重建实例，避免图表闪烁。

## 五、小样本降级

演示库/新账号只有几条记录时，图表反而暴露"没数据"：10 条散在 38 类里，每根柱子都是 1。

| 记录数 | 表现 |
|---|---|
| 0 | 只显示 4 个数字卡 + 引导提示「去识别页上传一张」 |
| 1 ~ 9 | 显示数字卡 + 提示「累计到 10 条后显示分布图」 |
| ≥ 10 | 正常出三张图 + OOD 卡 |

阈值 `MIN_CHART_TOTAL = 10`（`HistoryPage.jsx` 顶部常量）。

## 六、演示数据脚本

`scripts/seed_demo_records.py` —— 只在本地演示库使用，不参与线上逻辑。

| 特性 | 实现 |
|---|---|
| 幂等 | 默认「补齐到目标条数」，记录数已够就跳过 |
| 重置 | `--reset --yes`，只删该用户自己的记录 |
| 图片复用 | 从 `data/uploads` 现有文件随机取 `image_name`，不复制新文件（零磁盘增长，缩略图真实可渲染） |
| 分布贴近真实 | 番茄权重最高（6.0），置信度约 5% 落在 0.5 以下，近 7 天权重 ×3 |
| 防未来时间 | 今天抽到超过当前时刻会钳到 `now`（否则日趋势会画出未来数据） |

```bat
X:\Anconda3\python.exe scripts\seed_demo_records.py
X:\Anconda3\python.exe scripts\seed_demo_records.py --user demo --count 180 --days 30
X:\Anconda3\python.exe scripts\seed_demo_records.py --user demo --reset --yes
```

执行后回读校验并打印：总数、覆盖类别数、时间范围、平均置信度。

## 八、已知遗留

1. **构建体积**：主 chunk 1.66 MB（gzip 542 KB），`vite build` 有 >500 KB 警告。
   echarts 已按需引入，进一步优化需把 HistoryPage 改为 `React.lazy` 路由级懒加载。
   内网/单机部署可接受，公网首屏建议后续处理。
2. **缩略图黑块**：演示数据复用的部分源图本身是深色/灰度图，列表里看起来像占位符，非 bug。
3. **置信度口径**：见第三节。若要真正展示"可靠性分档"，需要在记录表里补存校准后置信度，
   属于表结构变更，本期未做。
