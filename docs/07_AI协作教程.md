# 07 AI 协作教程（实训验收用）

> 版本：V1.0 ｜ 适用对象：参与本项目的实训同学 / 希望用 AI 协作完成软件项目的开发者
> 目标：复盘「基于 CNN 的农作物叶片病害识别系统」如何用 AI 协作完成，提炼可复用的协作方法论。

---

## 1. 为什么写这篇教程

本项目从 **需求 → 设计 → 数据/模型 → 优化/部署 → 前端 → 文档** 全链路，均由「人（PM/开发）+ AI 助手」协作推进。本教程不堆砌概念，而是以**本项目真实走过的每一步**为例，说明：

- AI 在每个里程碑扮演什么角色、产出什么；
- 哪些事**必须人拍板**、哪些事**可放心交给 AI**；
- 如何用一套**节奏（备份 → 改 → 验证）**把 AI 的"快"变成"可控的快"。

> 全篇所述改动均有 `git` 提交记录与 `backups/` 备份可佐证，非凭空杜撰。

---

## 2. 协作总览：里程碑地图

| 阶段 | AI 主要角色 | 核心产出 | 协作节奏 |
|------|-----------|---------|---------|
| M1 设计 | 结构化撰写助手 | PRD、UI/UX、数据库设计、API 文档 | 人定口径 → AI 成稿 → 人校 |
| M2 数据+模型 | 代码生成 + 调参助手 | 预处理/增强脚本、训练代码、best 模型、评估报告 | 人定方案 → AI 实现 → 防泄漏验证 |
| M3 优化+部署 | 工程实现 + 评测助手 | 量化/剪枝模型、FastAPI 服务、压缩对比报告 | 人定目标 → AI 实现 → 三后端冒烟 |
| M4 前端+集成 | 联调 + 走查助手 | React 前端、前后端联调、完整 WebApp | 人定界面 → AI 落地 → 功能走查 |
| M5 测试+交付 | 审查 + 文档助手 | 测试报告、PPT、项目说明(README)、本教程 | 人提缺口 → AI 补齐 → 回归 |

**关键认知**：AI 不是"一次生成全部"，而是**每个里程碑内反复「提需求 → 出稿 → 审查 → 修改」**的迭代伙伴。本项目后期的大量工作，正是 M5 阶段对前序代码的**安全审查与低优先级打磨**（见第 4 节）。

## 3. 各里程碑 AI 协作实况

### 3.1 M1 设计：把"任务书"变成"可开发的文档"
- 人：明确任务书口径（如"26 类"实际为 PlantVillage **38 类**，经确认按 38 类）。
- AI：按 PRD 模板产出功能清单、验收标准（GIVEN-WHEN-THEN）、数据库表结构、API 契约。
- 产出：`docs/01~04`（PRD / UIUX / 数据库 / API）。

### 3.2 M2 数据+模型：防泄漏是 AI 帮上的关键一课
- AI 实现训练代码（ResNet18 + 加权损失 + 早停），但**初期按随机切分得到虚高 99.82%**。
- 人/AI 共同发现 **数据泄漏**（同一叶片近重复图跨训练/测试集），改用 **分组切分（aHash + 并查集）** 后诚实指标 **99.27%**。
- 教训：AI 不会自动替你发现数据科学陷阱，**关键指标必须追问"怎么切分的"**，并要证据。

### 3.3 M3 优化+部署：三后端压缩
- AI 实现 INT8 量化（−75% 体积、2× 加速、精度仅 −0.04pp）与结构化剪枝（−20%），并产出 `docs/06_模型压缩对比.md`。
- 推理引擎通过 `INFER_BACKEND` 开关切换，**对调用方透明**（这是 AI 在架构上做对的一点）。

### 3.4 M4 前端+集成：界面与联调
- AI 落地 React + Ant Design 前端（识别/历史/知识库/登录/个人中心 5 页），实现前后端联调闭环。

### 3.5 M5 测试+交付：审查 + 补齐（本教程所在阶段）
- AI 对已上线代码做**安全/健壮性审查**，发现并修复高危项（见第 4 节）；补齐 README、PPT、本教程。

## 4. M5 阶段：AI 做的"代码体检"与修复清单

M5 不只是写文档——更是对前序代码的一次**系统化审查**。以下均为本项目真实修复，按优先级：

### 4.1 高优先级（安全 / 数据正确性）
| 问题 | 原实现 | AI 修复 |
|------|--------|---------|
| 密码存储 | `sha256(salt+password)` 快哈希 | 改 **bcrypt**；兼容旧账户、登录自动升级 |
| JWT 密钥 | 硬编码 | 改 **环境变量** `JWT_SECRET`，缺失仅开发告警 |
| CORS | 通配 `*` | 改 **白名单** |
| 数据库字段 | 作物/病害拆分错误 | 用 `disease_knowledge.json` 正确拆分 |

### 4.2 中优先级（健壮 / 工程）
| 问题 | AI 修复 |
|------|---------|
| `DATA_ROOT` 硬编码 | 改环境变量，延迟回退内置 38 类 |
| 剪枝比例未记录 | 写入 checkpoint 元数据 |
| 模型名硬编码 | 抽为 `BEST_MODEL_PATH` / `LAST_MODEL_PATH` 常量 |
| 上传前校验 | 内存 `Image.verify()` + 异常清理孤儿文件 |
| 仓库治理 | `git init` + `.gitignore`（忽略大文件/运行时产物/node_modules） |
| 依赖清理 | 移除 `opencv-python`，锁定 `bcrypt==3.2.0` |

### 4.3 安全加强（A–E，高危信息泄露等）
- **A**：移除 `app.mount("/static", ...)`，数据与上传图不再可 `GET` 公开下载；
- **B**：限流取**真实客户端 IP**（读 `X-Forwarded-For` / `X-Real-IP`）；
- **C**：CSV 导出改 `FileResponse` + `BackgroundTask` 清理临时文件，并修复 `/records/export` 被 `{rid}` 抢匹配的 **路由顺序 bug**；
- **D**：SQLite 改 **WAL** 模式 + `busy_timeout`，缓解并发锁；
- **E**：错误返回**真实 HTTP 状态码**（404/400/401/409/413/429/500）。

### 4.4 低优先级（体验 / 可维护性）
| 问题 | AI 修复 |
|------|---------|
| `top_k` 误导 | 单例曾冻结 `top_k`；改为**逐次调用参数**，API 暴露 `top_k` 查询参数 |
| 超大图/EXIF | 推理前 **EXIF 校正 + 预缩放**（最长边 ≤ 512），避免手机照被喂歪 |
| 字体硬编码 | `evaluate.py` 硬编码 `C:/Windows/Fonts`；改三级回退，换平台不再出豆腐块 |
| 脚本散落 | `predict_one.py` / `predict_smoke.py` 归位 `scripts/` |
| 自动化测试 | 新增 `pytest` 11 用例（纯函数/字体/API 冒烟），模型缺失自动 skip |

> 上述每一项 AI 都**先给代码证据**，再落地修改，而非"声称已修"。这是协作的铁律。

## 5. 核心方法论：把 AI 的"快"变成"可控的快"

### 5.1 节奏：备份 → 改 → 验证
每次动手前：
1. **备份**：`cp 待改文件 backups/日期-pre-xxx/`（本项目 `backups/` 即回滚点）；
2. **改**：小步修改，单文件单职责；
3. **验证**：跑测试 / 冒烟 / 端到端，确认无回归再提交。

本项目所有修改均经此节奏，累计提交：`7f75258`、`b3288e4`、`c00f6cf`、`fdc0d28` 等。

### 5.2 原则：confirm-then-proceed
- **有歧义先问清**，等确认（"已确认"）再动手；
- 方向明确时用**简洁序号拍板**（如"1–5 都不需要，6、是的"）；
- 不改"凭印象"——凡依赖 AI 能力的结论，**先要证据**（测试输出、截图、代码行）。

### 5.3 给 AI 的"好指令"特征
| 差的指令 | 好的指令 |
|---------|---------|
| "优化一下代码" | "先修高优先级的 1–4：密码哈希、JWT、CORS、DB 字段，给证据" |
| "前端弄好看点" | "识别页上传区用 Upload.Dragger，结果页 Top-3 用 Progress 条形图" |
| "测试通过了吧" | "跑 `pytest -v`，把失败用例贴出来" |

## 6. 使用 AI 协作的禁忌（踩坑总结）

1. **不要盲信指标**：AI 生成的"99.8% 准确率"要追问切分方式（本项目就因此发现数据泄漏）。
2. **不要跳过验证**：AI 说"已修复"不等于真的修复，必须看测试/截图/代码。
3. **不要一次性大改**：大改动分批、可回滚，出问题能定位到具体一步。
4. **不要让 AI 替你定业务边界**：38 类 vs 26 类、做/不做哪些模块，必须人拍板。
5. **敏感信息不上传**：密钥走环境变量，不写进代码或文档正文。
6. **CMD 用户注意**：给 Windows CMD 命令**不要用 `<占位符>` 写法**（会被当重定向符），优先交互式 `set /p` 或给出可直接复制的完整命令。

## 7. 给实训同学的上手清单

1. 读 `README.md` 把项目跑起来（后端 `uvicorn src.api.main:app` + 前端 `npm run dev`）。
2. 读 `docs/05_测试报告.md` 理解"防泄漏"为何重要。
3. 跑 `py -3.12 -m pytest -v` 看自动化测试如何兜住回归。
4. 翻 `backups/` 与 `git log`，观察"备份 → 改 → 验证"在真实提交中的体现。
5. 对照第 4 节清单，挑一个你自己的项目，用同样的审查视角做一次"代码体检"。
