# 14 · 置信度校准（Confidence Calibration）

> 目标：让模型输出的「置信度」在**真实田间场景**里也变得可信——既不过度自信地误导农户，
> 也不无谓地压低实验室域的可用性。

---

## 1. 问题：实验室域很准，真实域严重过自信

模型在 PlantVillage（实验室风格、单株居中、干净背景）上测试准确率 **99.27%**，
置信度与准确率高度一致（ECE≈0.003，近乎完美校准）。但同一套 softmax 置信度放到
**真实田间照片（PlantDoc）**上就完全失效：

| 指标 | PlantVillage 测试集 | PlantDoc test（真实域） |
|---|---|---|
| Top-1 准确率 | 99.27% | 17.5%（不指定作物）/ 43.6%（指定作物） |
| 平均 softmax 置信度 | 0.987 | 0.727 |
| 高置信（>0.9）样本 | — | 43 张 |
| 其中判错 | — | **32 张（74.4%）** |

即：模型对真实田间照片**自报 73% 把握，实际只对了 17.5%**；最危险的是那 43 张「高置信」
样本里 32 张是错的——直接照着施药会出事。这正是需要校准的地方。

---

## 2. 方案：温度缩放（Temperature Scaling）

对 logits 除以温度 T 再 softmax：`p = softmax(z / T)`。T>1 让分布更平坦、抑制过自信。
T 在**有标签真实域**（PlantDoc train，648 张，与评估集零重叠）上用 NLL 拟合：

| 路径 | T_global | T_crop（指定作物） | ECE(前→后) | 高置信错判(前→后) |
|---|---|---|---|---|
| 真实域 | 6.05 | 9.55 | 0.552→0.086（global）/ 0.351→0.127（crop） | 32 张 → **0 张** |

校准**只改置信度数值、不改 Top-1 排序**（单调变换）→ 准确率完全不变，印证理论。

---

## 3. 为什么是「两个温度、两条路径」（不是同一个 T）

实测**同一个 T 无法同时适配两个域**：

- PlantVillage 图需要 T≈1（T=6 时把 99% 准确率图的置信压到 0.325，严重欠自信）；
- PlantDoc 图需要 T≈6~10（T=1 时 0.727 但准确率仅 17.5%）。

因此系统内并存两套温度（最易混淆处，已在 `predict.py` 注释固定）：
- `self.temperature`（T=1.0，PlantVillage 拟合）→ 用于 **MSP 判据 + 原始 `confidence`**；
- `self.calib["T_*"]`（T≈6~10，PlantDoc 拟合）→ 只用于**对外展示的 `confidence_calibrated`**。

> ⚠️ 关键不变量：校准路径**绝不**触碰 OOD 判据 `msp` / `leaf_prob`——它们必须停留在
> T=1.0 尺度（0.98 阈值就是在该尺度上定的）。若把大 T 灌进 MSP，OOD 拒识直接失效。
> 该不变量由 `tests/test_api_smoke.py::test_predict_calibration_fields` 守护。

---

## 4. 为什么放弃「域判别器自动选温度」

曾尝试训练一个「实验室图 vs 田间图」二分类头，想按域自动选 T。验证发现致命漏洞：
**120 张真实图里有 16 张（13.3%）被误判成实验室域**——而这 16 张里 **12 张（75%）实际判错**，
且多张置信 0.96~1.00。按域选温度等于把最危险的「自信地错」放过去了。

结论：**不自动判别域，统一用保守的真实域温度 + 可靠性分级**。宁可把真实场景统一说「仅供参考」，
也不让漏网的过自信样本蒙混过关。

---

## 5. 可靠性分级（Reliability Tiers）

把 `confidence_calibrated` 映射为三档，前端直接用彩色标签表达「该信多少」：

| 分档 | 阈值 | 实测判对率（crop 模式） | 前端文案 |
|---|---|---|---|
| high | ≥0.55 | 89.7% | 校准：结果较可靠（绿） |
| medium | 0.25–0.55 | 42.0% | 校准：结果仅供参考（金） |
| low | <0.25 | 22.6% | 校准：结果可能不可靠（红） |

阈值由实测确定（见 §6 的回归脚本输出）。不指定作物时 93% 样本落 low——与「准确率仅 17.5%」一致。

---

## 6. 落地与回归

| 层 | 改动 |
|---|---|
| 训练/评估 | `scripts/calibrate_domain.py`（在 PlantDoc train 拟合 T，产出 `models/calibration_domain.json`，含 `T_global`/`T_crop`/分档阈值/ECE 前后对比） |
| 推理 | `src/model/predict.py`：`_load_domain_calibration()` 加载真实域温度；`_infer()` 新增「路径 B」算 `confidence_calibrated`；`reliability_of()` 做分档 |
| 配置 | `src/config.py`：`CALIBRATION_DOMAIN_PATH` / `CALIBRATION_DOMAIN_ENABLE` / `RELIABILITY_HIGH=0.55` / `RELIABILITY_MEDIUM=0.25` |
| API | `src/api/main.py`：响应新增 `confidence_calibrated` / `reliability` / `calibration_enabled` |
| 前端 | `src/web/src/pages/DetectPage.jsx`：结论区显示「真实场景校准：xx%」+ 彩色可靠性标签 |
| 测试 | `tests/test_api_smoke.py::test_predict_calibration_fields`：守护三字段契约 + 分档自洽 + OOD 判据不被校准改动 |
| 文档 | 本文件 + `docs/04_API接口文档.md` 响应字段 |

**重新生成校准**（数据或阈值调整后）：

```bash
py -3.12 scripts/calibrate_domain.py
# 产出 models/calibration_domain.json（已入库，运行时依赖）
```

**关闭校准**：设 `CALIBRATION_DOMAIN_ENABLE=0`，后端 `calibration_enabled=false`，前端退化为原逻辑。

## 7. 端到端实测一例

真实图 `outputs/realtest_test/apple_cedar_rust/...jpg`（苹果桧锈病）：

```json
{ "confidence": 0.9315, "confidence_calibrated": 0.0989,
  "reliability": "low", "msp": 0.9315, "likely_not_leaf": false }
```

模型自报「番茄晚疫病 93%」，校准后仅 **9.9%**、可靠性 low——前端红字提示「结果可能不可靠」。
这正是校准要解决的「自信地错」问题。
