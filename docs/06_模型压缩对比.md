# 06 模型压缩对比报告（D 方案：量化 / 剪枝）

> 版本：V1.0.0 ｜ 生成日期：2026-10-13 ｜ 关联文档：`05_测试报告.md`
> 目标：在「诚实评估（99.27%，见 05 报告）」的 fp32 基线之上，验证 INT8 量化与结构化剪枝两类压缩手段的**体积 / 精度 / 推理延迟**权衡，为边缘 / CPU 部署选型提供依据。

---

## 1. 评测环境与方法

| 项 | 配置 |
| --- | --- |
| 硬件 | 本机 CPU（压缩目标即 CPU / 边缘部署，故延迟统一在 CPU 上测，保证可比性） |
| 软件 | Python 3.12 + PyTorch 2.5.1 + qnnpack（INT8 后端） |
| 数据集 | 防泄漏测试集（`data/split/test/`，归组切分后，无近重复泄漏） |
| 精度口径 | 与 05 报告一致：**不使用 AMP、单图真实推理、加权交叉熵背景下的 test 准确率 + 宏 F1** |
| 延迟口径 | 固定 dummy 输入 `(1,3,224,224)`，预热 5 次后取 50 次平均单图耗时（ms） |
| 复现脚本 | `python -m src.model.compare`（产出 `outputs/compare.json`） |

---

## 2. 核心对比结果

| 后端 | 方案说明 | 体积(MB) | 体积缩减 | 准确率 | 宏 F1 | 单图延迟(ms) | 加速比 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| **fp32** | 原始防泄漏 best（基准） | 44.9 | 0% | **99.27%** | **99.23%** | 22.75 | 1.00× |
| **quantized** | INT8 静态量化（qnnpack / CPU） | 11.2 | **−75%** | 99.23% | 99.20% | **11.16** | **2.04×** |
| **pruned** | 结构化通道剪枝（fp32，20% 中间通道） | 36.1 | −20% | 99.02% | 98.87% | 18.98 | 1.20× |

> 结论一句话：**INT8 量化以几乎无损（准确率仅 −0.04pp）换来 4 倍体积压缩与 2 倍推理加速，是边缘部署首选；结构化剪枝精度略低且压缩比有限，适合与量化叠加或作为精度敏感场景的温和方案。**

---

## 3. 三种方案详解

### 3.1 原始 fp32（基线）
- 文件：`models/best_resnet18_38.pth`（44.9MB）
- 即「C 方案防泄漏修复」后诚实评估最高精度模型（见 05 报告）。
- 优势：精度最高、结构标准、兼容性强；劣势：体积大、CPU 推理慢。

### 3.2 INT8 静态量化（D-2，已完成）
- 文件：`models/quantized_resnet18_38.pt`（11.2MB）
- 方法：`torch.ao.quantization.quantize_fx` + `qnnpack` 后端 + `Relu` 融合（`ConvReLU2d`）+ 校准集统计激活分布。
- 结果：体积 **−75%**（44.9 → 11.2MB），延迟 **−51%**（22.75 → 11.16ms），准确率 **99.27% → 99.23%**（仅降 0.04pp）。
- 适用：CPU / 移动端 / 边缘设备部署，对精度几乎零影响，强烈推荐作为生产默认。

### 3.3 结构化通道剪枝（D-1，已完成）
- 文件：`models/pruned_resnet18_38.pth`（36.1MB）
- 方法：仅剪 **残差块内部中间通道**（`conv1.out = conv2.in`，保持维度对齐），剪除 20% 中间通道后 GPU 短微调 4 epoch 恢复精度。
- 结果：体积 **−20%**（44.9 → 36.1MB），延迟 −16%（22.75 → 18.98ms），准确率 **99.27% → 99.02%**（降 0.25pp），宏 F1 99.23% → 98.87%。
- 适用：对精度更敏感、但仍需一定体积收益的 CPU 场景；或作为「剪枝 + 量化」级联压缩的第一阶段。

---

## 4. 精度损失根因分析

| 方案 | 准确率变化 | 宏 F1 变化 | 主要损失来源 |
| --- | --- | --- | --- |
| 量化 | −0.04pp | −0.03pp | INT8 低比特表示引入的极小舍入误差（校准后几乎可忽略） |
| 剪枝 | −0.25pp | −0.36pp | 中间通道被裁掉，残差块表达容量下降（近缘病害类目互混略增，与 05 报告第 4 类根因一致） |

> 两类压缩的精度损失均集中在 **近缘病害互混**（如玉米灰斑病 / 玉米斑点病、苹果黑星病 / 苹果锈病），这与 05 报告「错误根因」完全一致，非压缩引入的新问题。

---

## 5. 部署选型建议

| 场景 | 推荐后端 | 理由 |
| --- | --- | --- |
| 云端 GPU 服务 | fp32 | 精度最高，GPU 上体积与延迟非瓶颈 |
| 边缘 / 移动 / CPU 生产 | **quantized（INT8）** | 体积 −75%、速度 2×，精度几乎无损 |
| 精度敏感 + 需瘦身 | pruned（或 pruned+quantized 级联） | 温和压缩，可进一步叠加量化 |
| 演示 / 快速联调 | 任意（默认 fp32） | 接口统一，切换无成本 |

## 6. 推理接入方式（D-3，已完成）

`predict.py` 通过 `src/config.py` 的 `INFER_BACKEND` 开关切换后端，**对 `predict_image()` 调用方完全透明**，接口不变：

```python
# src/config.py
INFER_BACKEND = "fp32"        # 可选: "fp32" | "quantized" | "pruned"
QUANTIZED_MODEL_PATH = MODEL_DIR / "quantized_resnet18_38.pt"
PRUNED_MODEL_PATH    = MODEL_DIR / "pruned_resnet18_38.pth"
```

```python
# 调用方代码无需改动
from src.model.predict import Predictor
p = Predictor(top_k=3)            # 自动按 INFER_BACKEND 加载对应模型
res = p.predict_image(pil_image)  # 返回 top_k 类别 + 置信度
```

**三种后端已端到端冒烟验证**（同一张图 top-1 一致为「玉米灰斑病」）：
- fp32：conf = 0.9882
- quantized：conf = 0.9457
- pruned：conf = 0.7405

> 置信度差异来自压缩方式不同（INT8 校准温度、剪枝结构变化），top-1 类别一致，证明三后端语义等价。

## 8. 待确认 / 后续

1. **剪枝 + 量化级联**：当前两者独立产出，未验证「先剪枝再量化」的叠加效果（预计体积进一步下降、精度略降），如需可补充实验。
2. **量化 GPU 部署**：当前 INT8 用 qnnpack（CPU）。PyTorch CUDA 量化在本版本不支持，若需 GPU 量化需换 TensorRT / 其他后端。
3. **网页端**：D 方案仅涉及模型与推理后端，网页接入（前端选择压缩模型）未在本期范围，需后续联调。
