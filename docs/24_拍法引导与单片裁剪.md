# 拍法引导与单片叶片裁剪（对应 docs/23 发现）

> 起因：docs/23 外部域评估发现，农户真实使用中习惯拍**整株**照片，Top-1 仅 17.1%，
> 而单叶近景是 43.6%。本次要做的是「让用户拍对 / 裁对」，**不动模型**。

## 1. 先说结论

| 尝试 | 结果 | 是否上线 |
|---|---|---|
| 自动判断「叶片是否占满画面」（3 轮共 9 个指标） | **全部失败**，见第 2 节实测数据 | ❌ 未上线 |
| 前置拍摄引导卡（2 张内联 SVG 示例 + 3 条要点） | 无需算法，零误报 | ✅ 已上线 |
| 手动「框选单片叶片」裁剪（拖动 + 缩放，导出 448×448） | 端到端验证通过 | ✅ 已上线 |
| 结果区常驻轻提示（「结果不符？框选再识别」） | 弥补「自信但错误」无法用条件触发的问题 | ✅ 已上线 |

## 2. 为什么自动判断拍法不可行（负结果，重要）

三组实验均在「近景 43 张（test_images 叶片）」vs「远景 47 张（DigiGreen 番茄）」上做。

### 第 1 轮：颜色与连通域

| 指标 | 近景中位 | 远景中位 | 结论 |
|---|---|---|---|
| green_ratio（绿色占比） | 0.475 | 0.467 | 几乎相同 |
| largest_ratio（最大绿色连通块占比） | 0.456 | 0.435 | 几乎相同 |
| border_green（边框绿色占比） | 0.333 | 0.377 | 远景反而更高 |
| n_leaf_blobs（≥0.5% 的绿色块数） | 2 | 3 | 重叠 |

**根因**：整株番茄的叶片彼此重叠，绿色照样铺满画面、照样连成一片 —— 颜色类指标天然无法区分。

### 第 2 轮：尺度线索

| 指标 | 近景 p10 | 近景中位 | 远景中位 | 远景 p90 | 结论 |
|---|---|---|---|---|---|
| dt_rel（绿色区域内切半径/边长） | 0.020 | 0.042 | 0.020 | 0.058 | 近景 p10 落进远景分布内 |
| dt_p90 | 0.054 | 0.119 | 0.057 | 0.149 | 同上 |
| edge_den（边缘密度） | 0.034 | 0.095 | 0.128 | 0.297 | 方向对但重叠大 |

中位数有 2 倍差距，但**近景的 p10 与远景的 p90 交叉**，任何单阈值都会把大量近景判错。

### 第 3 轮：叶片检测头 3×3 分块打分

用现成的 OOD 叶片检测头逐块判「这块像不像叶片」，统计像叶片的块占比。

| 集合 | tile_leaf_frac 中位 |
|---|---|
| 近景（单片叶片） | 0.67 |
| 远景（整株） | **0.89** |

**方向是反的**。阈值扫描更直白：

| 阈值 | 近景误报 | 远景命中 |
|---|---|---|
| 0.60 | 42% | 17% |
| 0.70 | 65% | 23% |
| 0.78 | 79% | 38% |
| 0.90 | 81% | 57% |

近景误报始终远高于远景命中 —— 上线这个判据会让**大多数正常用户被要求重拍**，比不提示更糟。

> 三轮实验脚本保留：`scripts/analyze_framing.py`、`analyze_framing2.py`、`analyze_framing3.py`。
> 若要继续这条路，正确方向是训练一个「叶片实例分割」模型（需要像素级标注），
> 不是再试图像统计量。

## 3. 已上线的实现

### 3.1 前置引导卡 `components/ShotGuide.jsx`
- 两张**内联 SVG** 示意（✓ 单片近景 / ✗ 整株远景），不依赖静态图片资源，跟随主题色，任意分辨率不糊；
- 三条要点：叶子占满画面、病斑对焦清晰避免逆光、已成整株就用裁剪；
- 位置在上传拖拽区正上方，用户选图前就能看到。

### 3.2 单片裁剪 `components/LeafCropModal.jsx`
- 固定方形取景框（300×300），**拖动平移 + 滑块缩放（1×–4×）**，所见即所得；
- `cover` 基准缩放 + 偏移夹紧，保证任何缩放级别都不露空白；
- 导出 448×448 JPEG（`canvas.toBlob`，q=0.92），直接替换上传文件，**后端零改动**；
- 裁剪始终基于**原图**（`sourcePreview`），反复裁剪不累积画质损失。

### 3.3 结果区常驻提示 `pages/DetectPage.jsx`
条件式提示（仅低置信/非叶片时出现）在这种场景下**不会触发**：实测那张整株照被判成
「番茄花叶病毒病 76.2%、可靠性：较可靠」，各项判据都正常。因此改为结果卡底部常驻一行：

> 结果和实际情况不符？**框选单片叶片再识别一次** —— 整株或远距离拍摄是误判最常见的原因。

低置信时的醒目 Alert 保留，两者不冲突。

```
后端：X:/Anconda3/python.exe -m uvicorn src.api.main:app --host 127.0.0.1 --port 8000 --no-proxy-headers
前端：cd src/web && npm run dev

```

流程与结果：

| 步骤 | 观察 |
|---|---|
| 登录后进入识别页 | 引导卡正常渲染，两张 SVG 示意图无错位 |
| 上传 DigiGreen 整株照（00091.jpg，标注 Healthy） | 预览正常 |
| 第一次识别 | 番茄花叶病毒病 **76.2%**、校准 67.5%、标「结果较可靠」（**错误**） |
| 打开裁剪弹窗、拖动 + 放大 | 图片铺满取景框、无露白，缩放生效 |
| 确认裁剪 | 预览变为方形近景，toast「已按单片叶片裁剪」 |
| 第二次识别 | 番茄叶霉病 **81.7%**、校准 76.0%（仍错，但已走通全链路） |
| 结果卡底部 | 常驻提示正常显示 |

> 第二次仍判错是因为脚本只放大到约 1.4×，框里仍是大半株；这恰恰说明
> **裁剪框的位置取决于用户**，工具只保证「能做到」，不保证「自动做对」。

控制台：修复 `Modal destroyOnClose` 废弃警告后，**无 console.error / pageerror / 请求失败**。

## 5. 已知限制

1. 裁剪完全依赖用户操作，无自动建议框（自动框需要叶片实例分割/检测模型，本轮已证明轻量启发式不可行）；
2. 裁剪后按 JPEG 重新编码，理论上多一次有损压缩（q=0.92，实测不影响识别）；
3. 引导文案目前是静态中文，未做多语言。
