# 基于 CNN 的农作物叶片病害识别系统

> 实训项目 · 农作物叶片病害智能识别 Web 应用（ResNet18 迁移学习 + FastAPI + React）
> 覆盖 **14 种作物、38 类病害及健康状态**，防泄漏诚实指标 **准确率 99.27% / 宏 F1 99.23%**。
>
> **当前部署权重（2026-10-27 起）**：真实域 4 倍加权微调版 `finetuned_v2_w4`，
> 实验室域 **99.04%**、真实域番茄 **45.2%**。与纯 PV 基线的取舍与全部对照数据见
> `docs/22_真实域加权与防泄漏对照实验.md`（交付包内位于 `03_模型训练与评估（任务3）/实验与分析文档/`）。

---

## 1. 项目简介

传统病害诊断依赖农技人员肉眼观察，经验依赖强、基层力量不足，常错过最佳防治窗口。本项目以 **ResNet18** 为骨干网络，构建一款浏览器端农作物叶片病害识别应用：

- 农户 / 农技人员 **上传叶片照片** → 系统自动识别病害类别；
- 返回 **置信度、Top-3 候选概率分布与防治建议**；
- 登录用户可保存 **识别历史** 并导出（CSV / JSON）。

系统定位为 **辅助识别与科普工具**，结果仅供参考，不能替代现场专业农技诊断。

## 2. 核心特性

| 特性 | 说明 |
|------|------|
| 38 类识别 | 14 种作物（苹果/蓝莓/樱桃/玉米/葡萄/柑橘/桃/甜椒/马铃薯/树莓/大豆/南瓜/草莓/番茄）的病害 + 健康子类 |
| Top-3 概率 | 返回 Top-1 与 Top-3 候选，概率条形图可视化，低置信度提示人工复核 |
| **非叶片输入拒识** | 独立「叶片 / 非叶片」检测头（冻结模型的 512 维池化特征 → 逻辑回归），与病害识别解耦，原模型精度不受影响。真实叶 vs 非叶 AUROC **0.99**（同分布留出）/ **0.76~0.97**（跨来源留一验证）；端到端 21 例验证 20/21：黑白漫画、界面截图、统计图表、文档截图全部拦截。详见 `docs/11_域适应与OOD检测实验.md` |
| **作物先验** | 识别页**必须先选作物**（列表内 14 种），后端把 softmax 限制在该作物的候选类内。真实田间照片多候选作物 Top-1 **15.8% → 43.6%**（+27.7pp），不动模型权重。根因是模型「只看斑点纹理、不看作物」——苹果锈病会被判成玉米灰斑病且置信度 96%+。作物清单走 `GET /crops`，新增作物无需改前端。详见 `docs/05_测试报告.md` 第 11.9 节 |
| **批量识别** | 「单张 / 批量」模式切换，一次最多 **9 张**逐张识别，每张都写入历史。**整批共用同一个作物**：页面常驻「必须同一种作物」警告，开跑前弹确认框写明张数与作物（混入其他作物会被强行判成本作物病害，比不选作物更误导）。已选图片以 3 列缩略图逐张可见，供识别前自查；单张失败只进失败清单、其余照常出结果；结果点开可单独框选重识别 |
| 防治知识库 | 38 类病害的「症状 / 病因 / 防治 / 治疗」全量知识卡，**左栏作物导航 + 按作物分组**，每类配 3 张数据集实拍参考图（`scripts/build_disease_refs.py` 可复现） |
| 用户体系 | 注册 / 登录 / 登出（JWT）、个人信息管理，密码 bcrypt 加盐哈希 |
| 历史记录管理 | 登录用户保存识别记录；支持**自定义命名、人工判卷（识别正确 / 识别错误，可选补记实际病害）、按判定筛选、删除（含清理磁盘原图）**、图片放大查看、CSV / JSON 导出。列表为服务端分页，页脚显示「第 X-Y 条 / 共 N 条」 |
| 人工核对统计 | 按人工判卷结果算准确率，**分母是已核对条数**（不是总识别数）；卡内「识别错误 / 未核对」数字可点击下钻到列表筛选；与作物分布、置信度分布、识别趋势、非叶片拦截共 5 张图，均可在个人中心按需隐藏 |
| 三后端模型 | fp32 / INT8 量化 / 结构化剪枝，通过 `INFER_BACKEND` 一键切换，对调用方透明 |
| 安全基线 | bcrypt 密码、JWT 密钥环境变量、CORS 白名单、真实 HTTP 状态码、静态目录不暴露、SQLite WAL 并发保护 |
| 自动化测试 | `pytest` 39 用例（纯函数 / 字体 / 字段加密 / OOD 监控 / 判定与实际病害联动 / 批量识别契约与前后端上限一致性 / API 冒烟），模型缺失自动跳过 |

## 3. 效果指标（防泄漏诚实值）

> 数据集 PlantVillage，38 类 / 约 5.4 万张；采用 **分组切分（group-aware split）** 消除近重复泄漏（详见 `docs/05_测试报告.md`）。

| 指标 | 数值 | 任务书要求 |
|------|------|-----------|
| 整体准确率 | **99.27%** | ≥ 85% ✅ |
| 宏平均 F1 | **99.23%** | 各类 F1 ≥ 0.80 ✅ |
| 校准误差 ECE | 0.0028 | — |
| 38 类最低 F1 | 0.9524（玉米灰斑病） | ≥ 0.80 ✅ |

> 上表 99.27% 是**纯 PlantVillage 训练基线**（`backups/2026-10-20-pre-finetune`）的成绩。
> 2026-10-27 起线上部署的是**真实域 4 倍加权微调版**，同口径实测 **99.04%**（−0.23pp，约 1 张图），
> 代价换来真实域番茄 **26.3% → 45.2%（+18.8pp，McNemar p=0.0001）**。这是一次有意的取舍，不是退化。

### 外部验证：真实网络照片（重要）

上表是**实验室数据**上的指标。用从未参与训练的 PlantDoc test（120 张真实田间照片 / 27 类）复测：

| 指标 | 实验室（PlantVillage） | 真实网络照片（PlantDoc test） |
|---|---:|---:|
| Top-1 准确率 | 99.27% | **17.5%** ［95%CI 11.7~25.3］ |
| Top-3 准确率 | — | 38.3% |
| 作物级准确率 | — | 32.5% |
| 真实叶片被误判为「非叶片」 | 5.4% | 5.0% |
| **Top-1（用户指定作物后）** | — | **43.6%**（多候选作物） |

**域间隙约 82 个百分点**（不指定作物时）。系统为此提供两个正交的工程手段：
**叶片检测头**解决「这是不是叶片」（误判 5%），
**作物先验**解决「是哪种作物的哪种病」（多候选作物上 15.8% → 43.6%）。

即便如此，这仍决定了系统定位：**适用于特写/背景干净的单叶照片，不能作为田间用药依据**。
证据（对比图 + 逐张明细）见 `docs/05_测试报告.md` 第 11 节、`outputs/web_eval_sheet.png`。

### 模型压缩对比（边缘 / CPU 部署选型）

| 后端 | 体积 | 体积缩减 | 准确率 | 单图延迟(CPU) | 加速比 |
|------|------|---------|--------|--------------|--------|
| fp32（基线） | 44.9 MB | 0% | 99.27% | 22.75 ms | 1.00× |
| **INT8 量化** | **11.2 MB** | **−75%** | 99.23% | **11.16 ms** | **2.04×** |
| 结构化剪枝 | 36.1 MB | −20% | 99.02% | 18.98 ms | 1.20× |

> **结论**：INT8 量化以几乎无损（仅 −0.04pp）换来 4 倍体积压缩 + 2 倍推理加速，是边缘 / CPU 生产部署首选。详见 `docs/06_模型压缩对比.md`。

## 4. 技术架构

> 架构图为矢量 SVG：`docs/assets/architecture.svg`（交付包内为 `01_需求与设计（任务1、5）/系统架构设计图.svg`），可单独打开或直接用于 PPT。
> 四层：客户端 → 接入层（Nginx / TLS）→ 服务层（FastAPI）→ 推理引擎 + 数据层。

| 层 | 技术 |
|----|------|
| 前端 | React 18 + Vite 5 + Ant Design 5（响应式，PC / 移动端同套界面） |
| 接入 | Nginx 终止 TLS + 托管 `dist/` + `/api` 反代；开发用 Vite proxy |
| 后端 | FastAPI + Uvicorn + Pydantic，RESTful API（`/api/v1`） |
| 模型 | PyTorch + torchvision ResNet18（ImageNet 预训练 + 迁移学习微调） |
| 推理 | `src/model/predict.py`，`INFER_BACKEND` 切换三后端，温度缩放校准置信度；独立叶片检测头做非叶片拒识 |
| 数据 | SQLite（`WAL` 模式，外键约束，并发保护），用户 / 历史 / 病害知识 / 配置 |

## 6. 快速启动

### 6.1 后端（推理 + API）

```bash
# 1) 安装依赖（建议在虚拟环境）
pip install -r requirements.txt

# 2) 启动 FastAPI（项目根目录执行，确保根目录在 PYTHONPATH）
uvicorn src.api.main:app --host 0.0.0.0 --port 8000 --reload --no-proxy-headers

# 3) 浏览器打开接口文档
#    http://127.0.0.1:8000/docs
```

> **⚠️ `--no-proxy-headers` 不可省略（安全）**
> uvicorn **默认启用代理头信任**，且默认信任来自 `127.0.0.1` 的转发头 —— 它会在应用层
> 之前用 `X-Forwarded-For` 覆写客户端 IP，使接口限流可被一行请求头绕过（实测连续 65 次
> 请求一次未拦）。仅当确实部署在可信反向代理之后时才应改为
> `--proxy-headers --forwarded-allow-ips="代理服务器IP"` 并设置 `TRUST_PROXY=1`。
>
> 另注意：`--host 0.0.0.0` 会把服务暴露给同网段所有设备，本地开发建议改用 `127.0.0.1`。

> 推理后端通过 `src/config.py` 的 `INFER_BACKEND` 选择：`"fp32"`（默认）/ `"quantized"` / `"pruned"`。
> 生产环境请设置 `JWT_SECRET` 与 `DATA_ROOT` 环境变量（详见 `src/config.py` 注释）。
> **未设置 `JWT_SECRET` 时服务仍可启动**（每次启动生成随机密钥），但进程重启会让所有登录态失效。

### 6.2 前端（Web 客户端）

```bash
cd src/web
npm install
npm run dev          # 开发服务器，默认 http://127.0.0.1:5173
# 或 npm run build && npm run preview  # 产物预览
```

> 前端 `src/web/src/api/http.js` 中 `USE_MOCK` 控制是否走本地 mock 数据（默认 `false`，联调真实后端）。
> 后端未就绪时置 `true` 可独立预览界面。

## 8. API 概览（`/api/v1`）

| 接口 | 方法 | 说明 |
|------|------|------|
| `/health` | GET | 健康检查 |
| `/auth/register` | POST | 注册（用户名/邮箱 + 密码） |
| `/auth/login` | POST | 登录，返回 JWT |
| `/auth/me` | GET | 当前用户信息（需鉴权） |
| `/auth/logout` | POST | 登出 |
| `/predict` | POST | 上传叶片图，返回 Top-K 病害 + 置信度 + 防治建议（可选 `top_k`、`crop`）；登录时额外返回 `record_id` |
| `/predict/batch` | POST | **批量识别**：`files` 1~9 张 + **必填** `crop`，返回每张结果 / 失败清单 / 汇总；单张失败不影响整批 |
| `/crops` | GET | 当前支持的作物清单（前端不硬编码） |
| `/diseases` | GET | 38 类病害知识查询 |
| `/diseases/{did}` | GET | 单条病害详情 |
| `/records` | GET / POST | 识别历史列表（服务端分页 `?page=&size=`）/ 保存 |
| `/records/{rid}` | GET / PATCH / DELETE | 历史详情（720px 预览图 + Top-3）/ 改名与人工核对 / 删除 |
| `/records/export` | GET | 历史全量导出（CSV / JSON，响应后清理临时文件） |
| `/records/ood-stats` | GET | 非叶片判据的近 N 天分布（运行期漂移监控） |
| `/stats/overview` | GET | 历史页聚合统计（含人工核对准确率） |

> 路由声明顺序：`/records/export`、`/records/ood-stats` 必须排在 `/records/{rid}` **之前**，否则会被当成 `id` 解析（FastAPI 按声明顺序匹配）。

完整字段与示例见 `docs/04_API接口文档.md`。

## 9. 测试与质量基线

```bash
# 自动化测试（模型缺失时相关用例自动 skip）
py -3.12 -m pytest -v

# 三后端推理冒烟（D-3，验证 fp32/quantized/pruned 端到端可用）
py -3.12 scripts/predict_smoke.py
```

质量基线（已修复并验证）：
- 密码 **bcrypt** 加盐哈希（兼容旧 sha256 账户，登录时自动升级）；
- JWT 密钥走 **环境变量**（缺失仅开发告警，不报错退出）；
- **CORS 白名单**，不再通配 `*`；
- 移除 `/static` 挂载，**数据目录（含数据库 / 上传图）不再可公开下载**；
- 错误返回 **真实 HTTP 状态码**（404/400/401/409/413/429/500）；
- SQLite **WAL** 模式 + 超时，缓解并发 `database is locked`。
